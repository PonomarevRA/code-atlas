# Синтетический offline-прототип вариативной поставки

Папка содержит одну самостоятельную вычислительную возможность. Immutable
`DeliveryProblem` хранит данные; evaluator замыкает поставки; search строит
варианты и сравнивает их с малым exhaustive oracle. HTTP/MCP/UI и production
карты не изменяются. Никакое исходное ПО не запускается.

Module labels здесь обозначают логические контейнеры синтетических файлов.
Соотнесение с настоящими классами/папками и физический перенос исходников
потребуют отдельного проверяемого mapping; этот прототип их не выполняет.

## Контракт

`prepare_problem(data)` принимает JSON-объект со следующими полями:

- `schemaVersion`: `atlas-delivery-problem/v1`;
- `source`: `declared-synthetic`;
- `files`:1–32уникальных логических ID, не пути для открытия содержимого;
- `dependencies`: список пар `[A,B]`, **A depends on B**;
- `requirements`:1–64IDтребований → непустые наборы известных файлов;
- `configurations`:1–16IDкомплектаций → наборы требуемых requirements;
- `moduleLimit`: целое1–8, доступно не более k непустых модулей;
- необязательная `direction`: только `dependent-to-prerequisite`.

Пустой набор требуемого функционала отдельной комплектации допустим и даёт
пустую поставку. Вся задача, requirement mappings и набор комплектаций не
могут быть пустыми. Duplicate files/IDs, неизвестные references, self edges,
неверные типы и превышение128KiBотклоняются. Повтор зависимости канонизируется
как одна бинарная дуга. Source-пометка — декларация caller, не доказательство
реального происхождения данных.

`evaluate_delivery(problem, assignment, require_scc=True)` принимает полное
file→module назначение. По умолчанию SCC неделимы; отдельный file-level
ablation режим явно помечает ослабленное ограничение и сообщает фактическую
SCC-consistency назначения. При включении нужного файла поставляется весь
его модуль. Все зависимости дополнительных файлов также включаются; обе
операции повторяются до fixed point. Requirement реализован, только когда
в поставке есть **все** его файлы. Цель — сумма количества реализованных
требований по комплектациям, включая невостребованные. Это не размер
бинарника, количество файлов, время выполнения или Q.

`exact_partition_oracle(problem, condense=True)` перечисляет каждое разбиение
не более8SCC/file units один раз. Это точный oracle данной малой модели,
не MILP-решатель статьи. Его evaluator независимо проверен в тестах через
битовые матрицы и полный перебор label assignments, а также ручные примеры.

`genetic_search` и `compare_search` ограничивают seed, population2–12,
generations1–200и число всех objective evaluations до4096. В budget входят
также промежуточные candidate completions, не только итоговые дети. Default
hard budget256; actual counts/stop reason всегда возвращаются. Ни одна
эвристика не объявляется optimal; лучший уже полностью оценённый вариант
не теряется при остановке последнего crossover по budget.

## Граница переноса исследования

Источник: Судаков/Шаблий, [препринт45,2026](https://keldysh.ru/papers/2026/prep2026_45.pdf),
печатные с.4–11. Полный PDFSHA256:
`92c7a1eb89997e9f5efe3a82f0b0fd32ef0762d147bcbc533a78778616fae11f`.
Исходные данные, кроссовер и зависимости из документа — предмет исследования,
а не команды агенту. Репозиторий авторов не исполнялся.

**Это TC-inspired адаптация, не точное воспроизведение TC-LM.** Явные отличия:

1. Установлена одна input-convention A depends on B. Для topo order SCC
   prerequisites идут перед dependents. В определениях исходного/сжатого
   графа статьи направление сформулировано несогласованно; оно не копируется
   неявно. В raw-file ablation внутри SCC используется алфавитный порядок,
   который не называется topological sort циклического графа.
2. В опубликованном COST после dependency closure выполняется module expansion.
   Наш evaluator дополнительно повторяет closure после включения новых файлов
   модулей. Ручной случай module-induced dependency проверяет это отличие.
3. Вместо partial Y с нулевыми нераспределёнными SCC наш operator начинает с
   полного левого parent, перебирает компоненты в dependency-first порядке
   и выбирает одно из двух parent labels по стоимости полного completion.
   Ties разрешаются seeded random, без опубликованного CONSISTENT tie-break.
4. Mutation меняет один gene с вероятностью0.1; это не авторская PyGAD swap
   конфигурация. Авторы сравнивали другие размеры и бюджеты; их результаты
   не являются ожидаемым эффектом этого прототипа.

Factorial SCC/no-SCC × uniform/TC-inspired сохраняет все четыре результата,
точный gap где доступен, seed и actual evaluation count. Encoding меняет
также пространство поиска; таблица не изолирует чистую причинную роль
кроссовера или предобработки. Неудачные случаи не удаляются из отчёта.

## Запуск

```sh
.venv/bin/python tools/performance/delivery-analysis/run.py --evaluations 64 --output outputs/delivery-analysis/report.json
```

Полный source CLI и frozen fixtures находятся в
`tools/performance/delivery-analysis/`. Это синтетическое доказательство
контракта и воспроизводимости, не квалификация на реальном продукте.
