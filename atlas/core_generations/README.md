# Поколения вычислительных workers

Это самостоятельный модуль приложения для opt-in расчёта проекций модулей.
Обычный запуск Atlas продолжает использовать inline-расчёт. Единственное
приложение владеет ProjectStore, maintenance, HTTP/MCP-соединениями, заданиями,
курсорами и проверкой актуальности snapshot. Дочерний процесс получает только
JSON уже захваченной проекции и вычисляет assessment/comparison. Второй store
не создаётся, server.lock не обходится.

`build_bundle(source_root, destination, generation_id=...)` создаёт новый локальный
source-артефакт из фиксированного списка файлов. Это внутренний deployment API;
пути и код не принимаются от HTTP/MCP-клиента. Manifest фиксирует protocol,
semantic/storage профиль, точные версии Python/NetworkX и хеш каждого файла.
`BundleArtifact` включает ожидаемый хеш manifest. Это контроль идентичности
байтов, а не аутентификация издателя. Исполняемый код артефакта доверенный;
отдельный процесс не является sandbox для чужого кода.

`CoreGenerations.prepare(artifact, timeout=10)` проверяет профиль и байты,
копирует проверенное содержимое в собственный временный каталог и запускает
новый процесс Python с `-I`. Worker импортирует этот source bundle. Readiness
требует identity/PID/хеши и успешный настоящий расчёт маленькой canary-проекции.
Ошибка подготовки сохраняет прежнее активное поколение.

`activate(generation_id)` атомарно меняет поколение для будущих запросов.
`compute(projection, algorithms=..., seed=42, resolution=1.0, timeout=30,
cancel_event=None)` закрепляет выбранное поколение и выполняет ровно один
запрос. Результат — `{assessment, comparison}`. Ошибки содержат `code/status`.
Один worker допускает один in-flight запрос; избыток получает busy429.
Одновременно сохраняются максимум два поколения; скрытой очереди нет.
Сообщение ограничено8MiB, source bundle2MiB. Это бюджеты протокола/источников,
а не измеренная граница RSS или production capacity.

`retire(generation_id, deadline=...)` принимает абсолютный `time.monotonic()`
deadline не дальше120секунд; по умолчанию ждёт1секунду. Активное поколение
сначала требуется сменить. Старое поколение больше не принимает запросы;
завершение закреплённых запросов ожидается до deadline, затем только его
процесс принудительно завершается. Timeout/cancel_event также завершают
поражённый worker. Запросы не переносятся и не повторяются на новом поколении.
`close()` закрывает все собственные процессы/каналы/временные копии.

Ни jobs/cursors, ни мутации не пересылаются worker: они остаются в стабильном
host. Пилот не заменяет всё ядро приложения и не обновляет остальные tools.
Сохранение MCP tool descriptors и работа старого клиента доказываются отдельным
source integration harness после композиции. Наличие PID или одинаковый список
tools само по себе не доказывает совместимость поведения.

Frozen/native выпуск требует отдельного runtime resolver и exact-byte старого
reader proof. Текущий source Python pilot этого не квалифицирует и не меняет
установленные приложения или живые пользовательские подключения.
