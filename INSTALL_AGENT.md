## Русский

Скопируйте задание ниже локальному агенту с терминалом и доступом к выбранным вами каталогам. Укажите URL исходников (либо путь к существующему checkout), каталог установки и желаемый MCP-клиент. Если нужен первый анализ, отдельно укажите **разрешённый проект**. Облачный агент без доступа к машине не может установить локальный Atlas или подключиться к его loopback.

> Установи Code Atlas из исходников на этой машине и проверь результат по `docs/install.ru.md` репозитория. Если URL исходников или каталог установки не указан и не может быть однозначно определён из моего запроса, уточни только недостающее. Не выдумывай URL публичного релиза. Это разрешение создать локальное виртуальное окружение и установить зависимости из `requirements.lock` в выбранном каталоге; оно не разрешает менять системный Python или чужую установку.
>
> 1. Проверь ОС, CPU, доступный 64-битный Python 3.12/3.13, права на выбранный каталог и наличие существующей установки Atlas. Прочитай инструкции репозитория и проверь фактический CLI. Используй существующее подходящее окружение только после проверки. Не работай с правами root/администратора, не используй `sudo pip`, не меняй execution policy. Если нужен системный prerequisite, сообщи конкретное требование вместо самостоятельного повышения прав.
> 2. Сохрани существующие исходники, данные и настройки. Не клонируй поверх чужого checkout, не удаляй `.venv`, lock или каталог данных, не делай `git reset --hard`/`git clean`. Не останавливай неизвестные процессы. Если Atlas уже работает, проверь его адрес/версию и предложи использовать его; обновляй или заменяй его только если я это запросил.
> 3. Для новой установки создай `.venv`, установи закреплённые зависимости и выполни `pip check` и `python -m atlas.cli --version` именно executable этого окружения. Не скачивай embedding-модель, LLM или дополнительные языковые движки без отдельного запроса. Не считай снятие dependency pins исправлением платформенной ошибки.
> 4. Запусти Atlas в управляемом тобой терминальном сеансе; сохрани способ корректной остановки. Проверь напечатанный loopback URL и `/api/health`. Не создавай публичный listener. Если нужен отдельный экземпляр, используй и свободный порт, и новый каталог данных вне исходников. Не путай проверку HTTP с успешным анализом.
> 5. Строй первую карту только для проекта, который я явно указал для анализа. Если проект не указан, остановись на проверке приложения и подготовке MCP; не индексируй автоматически весь компьютер, родительскую папку или сам Atlas. Для разрешённого проекта дождись снимка и проверь известный файл/символ. Не называй статические факты результатом выполнения кода.
> 6. Если я запросил MCP, получи конфигурацию у запущенного экземпляра через `/api/agent-setup/config` (JSON) или `?format=toml` (Codex). Для репозитория возьми действительный projectId из `/api/projects` и включи его в запрос. До правки прочитай выбранный config клиента и сохрани копию; добавь/обнови только `code-atlas-agent`, сохранив все чужие серверы, поля и локальные skills. При неоднозначном существующем scope/entry уточни его назначение. Не выводи секреты config в отчёт. Если прямой доступ к config не разрешён, подготовь точный фрагмент для ручного объединения.
> 7. Переподключи MCP разрешённым механизмом клиента, затем начни новый чат или явно попроси меня сделать это, если сам не можешь. Реально проверь `list_projects`; для разрешённого проекта — `search_nodes`/`describe_node` с правильным snapshotId. Если клиентские инструменты в этом сеансе недоступны, честно оставь проверку подключения незавершённой; наличие config не выдавай за успешный вызов. Skills устанавливай целыми папками с references только при необходимости для выбранного клиента, не перезаписывая местные правки.
> 8. В итоговом отчёте раздели: установленное и запущенное; HTTP-проверку; карту; подключение/реальный MCP-вызов; найденные/совместимые/реально применённые движки. Укажи ОС/CPU/Python, выбранные каталоги и порт, команды повторного старта/остановки, ограничения и оставшиеся ручные действия. Не заявляй проверку Windows/Linux/native/AT, если она не выполнялась.

Эти инструкции разрешают только описанную установку. Доступ агента к MCP-фактам может передавать исходники выбранному AI-провайдеру согласно настройкам клиента. [Ручная установка](docs/install.ru.md).

## English

Copy the task below to a local agent with terminal access to the directories you choose. Supply the source URL (or existing checkout path), installation directory and intended MCP client. If you want a first analysis, separately identify an **authorized project**. A cloud-only agent cannot install software on your machine or access its loopback service.

> Install Code Atlas from source on this machine and verify it using the repository's `docs/install.en.md`. If the source URL or installation directory is missing and cannot be determined unambiguously from my request, ask only for what is missing. Do not invent a public release URL. This authorizes creating a local virtual environment and installing `requirements.lock` dependencies in the chosen directory; it does not authorize changing system Python or someone else's installation.
>
> 1. Check OS, CPU, available 64-bit Python 3.12/3.13, write access to the chosen directory and existing Atlas installations. Read the repository instructions and verify the actual CLI. Reuse a suitable existing environment only after checking it. Do not run as root/administrator, use `sudo pip`, or change execution policy. If a system prerequisite is missing, report the specific requirement instead of escalating privileges yourself.
> 2. Preserve existing source, data and settings. Do not clone over another checkout, remove `.venv`, a lock or data directory, or run `git reset --hard`/`git clean`. Do not stop unknown processes. If Atlas is already running, check its address/version and offer to reuse it; update or replace it only if I requested that.
> 3. For a new installation create `.venv`, install the pinned dependencies, then run `pip check` and `python -m atlas.cli --version` using that environment's executable. Do not download an embedding model, LLM or extra language engines without a separate request. Removing dependency pins is not a fix for a platform failure.
> 4. Start Atlas in a managed terminal session and retain the way to stop it correctly. Check the printed loopback URL and `/api/health`. Do not expose a public listener. An independent instance needs both a free port and a new data directory outside source trees. Do not equate HTTP readiness with successful analysis.
> 5. Build a first map only for a project I explicitly identified for analysis. If none is specified, stop at application verification and MCP preparation; do not automatically index the computer, a parent directory or Atlas itself. For an authorized project wait for a published snapshot and check a known file/symbol. Do not describe static evidence as code execution.
> 6. If I requested MCP, get configuration from the running instance's `/api/agent-setup/config` (JSON) or `?format=toml` (Codex). For repository work obtain a real projectId from `/api/projects` and include it in the request. Read and back up the intended client config first; add/update only `code-atlas-agent`, preserving other servers, fields and local skills. Clarify an ambiguous existing scope/entry. Do not expose config secrets in the report. If direct config access is not authorized, prepare the exact fragment for manual merging.
> 7. Reconnect MCP through the client's supported mechanism, then start a new chat or explicitly ask me to do so if you cannot. Actually check `list_projects`; for an authorized project check `search_nodes`/`describe_node` with the correct snapshotId. If the client's tools are unavailable in this session, leave connection verification explicitly incomplete; a config file is not a successful tool call. Install complete skill folders with references only when needed for the chosen client, preserving local edits.
> 8. In the final report separate: installed/running application; HTTP check; map; connection/actual MCP call; discovered/compatible/actually applied engines. State OS/CPU/Python, chosen directories and port, repeat-start/stop commands, limitations and remaining manual steps. Do not claim Windows/Linux/native/assistive-technology qualification you did not perform.

This task authorizes only the installation described above. Agent access to MCP facts may send source context to the AI provider selected in the client's settings. [Manual installation](docs/install.en.md).
