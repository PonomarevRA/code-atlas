# Моды Atlas и отдельный Graphify

Atlas теперь собирает карту в трёх слоях:

1. `atlas/integrations/graphify/` запускает Graphify и нормализует его результат. Старый `atlas/graphify_adapter.py` оставлен как совместимый вход.
2. `atlas/enrichment_pipeline.py` добавляет данные Atlas: поля, атрибуты, реализации, документацию и здоровье. Исходный результат Graphify не переписывается.
3. Моды меняют представление и вычисляют производные группировки. Каждый исходный ID сохраняется; мод группировки не может добавлять, удалять или дублировать узлы.

## Обновление Graphify отдельно

По умолчанию используется встроенная версия. Для независимого обновления создайте отдельное окружение, установите нужную версию и выберите его Python на странице **Моды и движок** (`/mods.html`):

```sh
python3 -m venv /absolute/path/graphify-runtime
/absolute/path/graphify-runtime/bin/python -m pip install 'graphifyy[mcp]==VERSION'
```

В Windows путь заканчивается на `Scripts/python.exe`, в Linux/macOS — на `bin/python`.
Для текущего проверенного набора зависимостей есть `resources/integrations/graphify/requirements.in`.
Переключение проверяет установку, не скачивает пакеты и не перестраивает существующие карты.
Следующее явное построение карты использует выбранный runtime и сохраняет его версию в metadata.
Atlas MCP также использует выбранный runtime. Неисправный выбранный runtime не заменяется молча встроенным.

`requirements-core.in` содержит зависимости Atlas, а корневой `requirements.in` объединяет оба набора для прежнего способа установки.
Standalone runner в `resources/integrations/graphify/runner.py` не требует установки Atlas в окружение Graphify.
Старая версия окружения может остаться для отката. Совместимость будущих версий Graphify следует проверять тестами адаптера: самостоятельное обновление не гарантирует неизменность формата поставщика.

## Установка мода

Откройте `/mods.html`, нажмите **Открыть каталог**, скопируйте папку мода, перечитайте каталог и включите выбранную версию.
Каталог — `<data-dir>/mods`; он отделён от анализируемых репозиториев.
Файлы модов в проекте автоматически не исполняются.
Пакет содержит `mod.json`, при необходимости JS-модуль и Python-группировку.
Установленный пример `readable-cards` показывает тему, действие двойного щелчка, декоратор и три группировки. По умолчанию он выключен.

Для декларативных анализаторов действует отдельный режим **Авто по файлам**:
встроенные языковые/библиотечные/build-моды выбираются при обновлении карты,
пользовательские analysis-only пакеты могут объявить `autoActivate`.
Явное выключение всегда приоритетно. Темы, группировки, workflows и исполняемые
моды требуют отдельного включения. [Правила и HTML-пример](html-mod.md).

Включение закрепляет хеш всего содержимого. После изменения файла мод нужно включить снова; новая группировка получает другой ключ кеша.
Зависимости объявляются через `requires`, включаются отдельно и загружаются раньше зависимых модов. Циклы запрещены.
Страница управления не импортирует исполняемые моды, поэтому доступна для восстановления.
**Отключить все** сохраняет пакеты и карты. `/?mods=off` открывает карту со встроенными группировками и без JS-модов.

## SDK v1

- JSON-тема задаёт цвет, обводку, скругление и размер названия карточки.
- JSON-действия назначают двойному щелчку выбор, раскрытие, вход, исходник или изоляцию.
- `activate(api)` регистрирует синхронные декораторы SVG-карточек. Они получают копию фактов, свой слой оформления и действия хозяина карты.
- Группировки могут быть декларативными (тип, язык, каталог, компоненты связности) либо Python-функцией `group(graph)`.
- Встроенные natural/Graphistry и прежние внутренние расширения сохраняются. Внешний API не заменяет HTTP-сервис, извлечение кода или глобальный renderer.

Полный контракт с примером: [SDK](../skills/code-atlas-extensions/references/mods-v1.md).
Он также доступен через `/api/agent-setup/skill?name=code-atlas-extensions&resource=references/mods-v1.md`.
Схема манифеста: `/api/mods/schema`.

Моды JS/Python — доверенный локальный код с правами пользователя приложения, **без OS sandbox**.
Проверки версии, размера и ID защищают контракт данных, но не делают чужой исполняемый код безопасным.
Python-группировка выполняется отдельным процессом из проверенной временной копии пакета; ограничены время и размер ввода/вывода.
Ошибочная группировка не публикуется, исходная карта и встроенные алгоритмы остаются доступны.
