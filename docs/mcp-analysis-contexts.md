# Адресное чтение анализа через MCP

Связи, синтаксис и подробности описания имеют разные продолжения. Все инструменты
работают с выбранным проектом и точным `snapshotId`; статические связи не являются
трассировкой исполнения.

## Связи

`get_neighbors` сохраняет прежние аргументы и добавляет необязательный `cursor`.
Передавайте возвращённый `nextRef` в следующий вызов с теми же `nodeId`,
`snapshotId` и `direction`. `nextRef: null` означает конец списка. Предел страницы
120 рёбер и 64000 UTF-8 байт; повторы связей и self-loop сохраняются. Повреждённый
селектор даёт400, изменившаяся область/ревизия —409. Контекст задачи не нужен.

## Временный контекст

1. Вызвать `open_analysis_context(snapshotId)` и сохранить `contextId`.
2. Передавать `contextId` в `get_method_flow_chunk` для переиспользования разбора
   неизменившегося файла между страницами и методами.
3. После работы вызвать `close_analysis_context(snapshotId, contextId)`.

Успешное полезное чтение продлевает срок до20 минут с последнего обращения.
Проверки существования и фоновая уборка его не продлевают. Исчезнувший контекст
даёт410, исчерпание числа контекстов —429. После перезапуска контексты создаются
заново. Закрытие или истечение во время вычисления исключает позднюю публикацию.

Каждый контекст принадлежит одной области проекта/снимка/настроек. Чужой
`contextId` и контрольная сумма селектора не предоставляют доступ. Применяются
обычные проверки локального API и выбранного MCP-проекта.

Резидентность ограничивается восемью контекстами,64 МиБ учитываемых данных
суммарно,16 МиБ на контекст,64 записями и200000 удерживаемыми AST-узлами на
контекст. Размер исходного текста/JSON и число узлов не являются гарантией RSS
нативного парсера. Крупный результат может обслужить запрос без сохранения в кэше.
На каждом обращении безопасный reader проверяет байты файла. Изменённый исходник,
грамматика или настройки не получают старое дерево. Ошибки парсера не кэшируются.

## Подробности, убранные из описания

`describe_node.sectionExploration` сообщает о `get_analysis_section`. Открыть
контекст и запросить раздел `methodFlow`, `documentation`, `calls`, `controlFlow`
или `parameterFacts` для выбранного узла. В ответе:

- `items[].value` содержит точное скалярное значение;
- `items[].ref` раскрывает дочерний объект/массив через `sectionRef`;
- `nextRef` продолжает эту же страницу через `sectionRef`;
- `containerKind`, `snapshotId`, `sourceHash` и `coverage` объясняют форму и границы.

Страницы целятся в24000 байт. Крупные строки выдаются последовательными частями
по1000 символов; вложенные объекты не сбрасываются в один большой ответ.
Селекторы закреплены за контекстом, узлом, разделом и хэшем источника.
Они также закреплены за содержимым раздела: изменение соседнего handler или
конфигурации отклоняет старое продолжение409. Описания с межфайловыми фактами
пересчитываются на чтении; кэширование только по выбранному файлу для них неверно.
20-минутное переиспользование разбора применяется к file-local AST-страницам.

Пагинация делает доступными уже вычисленные подробности. Она сохраняет
`sectionTruncated`, unsupported и UNKNOWN и не увеличивает лимиты языкового
анализатора. `get_method_flow_chunk` остаётся `syntax-outline`,
`flowStatus=not-computed`; AST-страница сама по себе не доказывает семантику вызова.

Исходные snapshots и сжатые CAS-объекты живут независимо от20-минутного RAM-кэша.
Закрытие контекста не удаляет историю и данные других задач.
