# Цветовые схемы Atlas

Откройте шестерёнку → **Цветовая схема** для быстрого переключения либо **Оформление** для создания палитры. Светлая и тёмная схемы встроены. Панели, карта, карточки и подсветка исходников используют семантические цветовые токены; смена схемы не перестраивает карту и не меняет её координаты, выбранный узел или URL.

На странице оформления нажмите «Скопировать выбранную схему», задайте уникальный идентификатор и название, измените цвета. «Создать и включить» создаёт новый JSON-мод в каталоге приложения и явно активирует его точную ревизию. Совпадающий идентификатор не перезаписывается. «Скачать mod.json» выгружает самостоятельный редактируемый пакет; положите файл в папку с идентификатором мода и включите её в каталоге модов. Для изменения существующей палитры можно отредактировать её JSON и активировать новую ревизию либо сохранить копию под другим именем.

Выбор хранится в localStorage отдельно для каждого браузерного профиля и native WebView. Вкладки одного origin синхронизируются. При запрете storage выбор действует до перезагрузки. Выключенный, изменённый или несовместимый мод больше не предоставляет схемы: используется последняя выбранная светлая/тёмная база. Для восстановления доступно `/appearance.html?mods=off`; страница управления не импортирует исполняемые моды.

## Декларативный контракт модов API v1

Существующее поле `theme` меняет отдельные поверхности карточек. Новое независимое поле `colorSchemes` добавляет именованные палитры всего приложения. Его можно сочетать с другими возможностями пакета. Цвета явно оформленных модом карточек сохраняют приоритет над общей палитрой.

```json
{
  "apiVersion": 1,
  "id": "ocean-colors",
  "name": "Ocean colors",
  "version": "1.0.0",
  "colorSchemes": [{
    "id": "night",
    "label": "Ocean",
    "base": "dark",
    "tokens": {"accent":"#8bc9fa", "cardHeader":"#293f4f"}
  }]
}
```

Полный пример: `mods/ocean-colors/mod.json`, изначально выключен. Один пакет содержит до 8 схем с уникальными локальными ID. В интерфейсе ID имеет пространство имён `mod:<mod-id>:<scheme-id>`; встроенные `light` и `dark` заменить нельзя. Пропущенные токены наследуются из `base`, разрешены только непрозрачные `#RGB`/`#RRGGBB`. Произвольные CSS, URL, неизвестные имена и поля отклоняются. Изменение манифеста меняет fingerprint и требует повторного включения.

Токены:

| Область | Имена |
| --- | --- |
| Приложение | `background`, `surface`, `surfaceAlt`, `text`, `muted`, `border` |
| Действия | `accent`, `accentSoft`, `onAccent`, `focus`, `selection` |
| Карта | `canvas`, `dot`, `card`, `cardHeader`, `cardBorder`, `edge` |
| Условия и ожидание | `control`, `controlText`, `waiting`, `waitingText` |
| Сообщения | `warning`, `warningSoft`, `error`, `errorSoft` |
| Подсветка кода | `keyword`, `string`, `number`, `comment`, `code`, `type` |

Пороговые оценки здоровья/сложности сохраняют прежние значения и подписи; SVG-бейджи сохраняют контрастные цвета. Палитра сама по себе не проверяет доступность произвольных пользовательских сочетаний. Авторам следует проверять контраст текста, выбранную карточку, условия, ожидание и неизвестные оценки в обеих раскладках.

## Границы реализации

`atlas/color_scheme_models.py` валидирует контракт, `atlas/color_schemes.py` объединяет включённые пакеты с базами, `atlas/color_scheme_api.py` публикует каталог и CSS. CSS выдаётся с того же origin и работает с `style-src 'self'`; тема не требует inline-стилей или ослабления CSP. `web/color-scheme.js` отвечает за выбор и хранение; `web/appearance-page.js` — за редактор. Существующие SVG presentation attributes связаны с токенами в `web/color-scheme.css`; новые компоненты должны использовать `var(--atlas-<token>)`.

Экспорт SVG/PNG — отдельный сохранённый артефакт. Эта возможность меняет интерфейс просмотра и не перекрашивает ранее сохранённые изображения. Windows/Linux используют тот же frontend; нативная сборка проверяется отдельно на каждой платформе.
