# Как работает Code Atlas

[Главная страница](../README.md) · [Библиотеки](third-party.md) · [Wiki](wiki/Home.md)

Atlas разделяет получение фактов, их хранение и представление. Graphify извлекает
базовую карту, собственные провайдеры дополняют её, а интерфейс и MCP читают
опубликованные снимки. Деревья документов строятся отдельным конвейером.
Для обычной работы не требуется генеративная модель.

## Путь от папки до карты

1. **Запуск.** [`atlas/cli.py`](../atlas/cli.py) выбирает порт и каталог данных,
   получает блокировку и запускает локальный сервер. Desktop-оболочка открывает
   тот же интерфейс через pywebview. Второй сервер для окна не создаётся.
2. **Сборка сервисов.** [`create_app`](../atlas/server.py) соединяет хранилище,
   API, здоровье, поиск, документы, моды и исследовательские процессы.
   Отдельные feature-модули регистрируют HTTP-маршруты.
3. **Регистрация проекта.** [`ProjectStore`](../atlas/store.py) сохраняет путь
   и управляет очередью построения. Локальные исходники остаются в своём каталоге.
   Для Git-источника отдельный сервис создаёт управляемый клон.
4. **Извлечение.** [`atlas/integrations/graphify/`](../atlas/integrations/graphify/)
   запускает выбранный Graphify runtime и нормализует его результат. Встроенный
   Graphify и внешний совместимый runtime можно обновлять отдельно от Atlas.
5. **Дополнение.** [`enrichment_pipeline.py`](../atlas/enrichment_pipeline.py),
   языковые и библиотечные правила добавляют атрибуты, входы, кандидатов реализаций,
   тестовые факты и инфраструктурные зависимости. Неопределённость сохраняется.
6. **Публикация.** Успешная сборка получает новый `snapshotId`. Ошибка не должна
   подменять предыдущий опубликованный снимок частично построенным графом.
7. **Производные задачи.** После публикации отдельно обновляются здоровье и,
   при доступной локальной модели, семантический индекс. Готовая карта ещё
   не означает завершения всех фоновых работ.
8. **Чтение.** API передаёт выбранную область интерфейсу или агенту. Пагинация,
   ограничения ответа и оконная отрисовка помогают работать с большими картами;
   усечение остаётся видимым.

## Пример: человек изучает HTTP-операцию

Пользователь выбирает вход из каталога. Atlas сопоставляет его с узлом метода,
строит статический путь и показывает вызовы. При раскрытии метода
[`atlas/flow_languages/`](../atlas/flow_languages/) выбирает языковой провайдер;
C# также использует свой анализатор. Результат приводится к общему контракту
с последовательностью шагов, ветвями, циклами, вызовами и исходными координатами.

[`web/`](../web/) рисует эти шаги общими карточками. Особая конструкция языка
может требовать расширения контракта, но не отдельного интерфейса для всего языка.
Если анализатор не поддержал конструкцию или достиг лимита, карта сообщает
ограничение. Раскрытие кандидатов интерфейсного вызова не доказывает, какая
реализация выбрана в реальном запросе.

Кнопка исходника читает файл из рабочей копии через сервер. Поэтому важны два
происхождения: факты снимка и текст, прочитанный сейчас. Пользователь проверяет
состояние источника, строку и хеш; один `snapshotId` не замораживает рабочие файлы.

## Пример: агент задаёт вопрос

[`atlas/agent_mcp.py`](../atlas/agent_mcp.py) запускает stdio MCP и обращается
к уже работающему HTTP-сервису Atlas. Он не создаёт второе хранилище и очередь
построения. Клиент получает список проектов, ищет символ, сохраняет `snapshotId`
и читает описание, соседей, исходники или документы в пределах бюджета ответа.

Объяснение пишет агент на основе этих фактов. Авторские заметки в сохранённом
виде отделяются от извлечённых связей. Если ответ усечён, агент продолжает чтение
страницами, а не считает первую страницу всем проектом.

При разработке можно зафиксировать здоровье рабочего дерева, оценить полный
черновик или диапазоны метрик будущих изменений, затем измерить результат.
Оценка — прогноз, документация в методе — наличие текста, а не проверка его смысла.
[Контракт здоровья](code-health.md) · [Работа с MCP](wiki/Agents-and-MCP.md).

## Документы и логи

[`atlas/document_service.py`](../atlas/document_service.py) управляет импортом,
а [`atlas/documents/`](../atlas/documents/) содержит провайдеры чтения и хранения.
Декларативный мод выбирает доверенный host-парсер. Исходный документ захватывается
локально, его bytes получают SHA256; результат сохраняется как ревизия с SQLite,
манифестом и привязкой к карте. Одинаковые артефакты можно переиспользовать.

Запросы дерева, содержимого и окна таблицы читают этот снимок. Они не запускают
заново Word, Excel, Helm или парсер оригинального файла. Координаты могут быть
строками, A1-ячейками, структурными OOXML-путями или страницами/bbox PDF.
Это разные типы координат; номер страницы Word не выдумывается.

Обновление оригинала не переписывает прошлую ревизию. Новый импорт создаёт новый
снимок. Очистка учитывает текущие снимки, сохранённые виды, поисковые индексы,
исследования и активные leases. Подробности: [документы и логи](document-maps.md).

## Поиск и LangGraph

Поиск символов использует имена и факты карты. Семантический поиск — отдельный
локальный индекс: FastEmbed вычисляет embeddings заранее установленной модели,
LanceDB хранит векторы. Без модели карта остаётся доступна; скрытой загрузки
весов во время запроса нет. [Подготовка](semantic-search.md).

[`atlas/research/`](../atlas/research/) использует LangGraph для управляемого
сбора фактов и SQLite checkpoints. Моды `langgraph-guide` и
`automatic-documentation` читают доступные источники и создают документ с их
происхождением. Сейчас это сбор и оформление фактов без подключённой LLM,
а не свободная генерация объяснений. [Сценарии и ограничения](mods-langgraph.md).

## Границы модулей и стороннего кода

- Интеграция Graphify отвечает за внешний движок; правила продукта остаются в Atlas.
- Языковой провайдер отвечает за синтаксис и общий контракт потока.
- Framework-мод отвечает за соглашения библиотеки: входы, аннотации, тестовые данные.
- UI рисует общую модель, а не самостоятельно угадывает семантику кода.
- MCP использует те же факты и сервисы, что и UI.
- Установка заменяет приложение; пользовательские данные хранятся отдельно.

Декларативные анализаторы не загружают Python из исследуемого репозитория.
Исполняемые пользовательские JS/Python-моды — отдельная доверенная возможность,
они работают с правами приложения. Парсеры документов имеют бюджеты и отдельные
worker-процессы, что не равнозначно изоляции средствами ОС.

## Где начать разработчику

| Изменение | Отправная точка |
| --- | --- |
| Запуск, каталог данных, окно | `atlas/cli.py`, `atlas/runtime_paths.py`, `atlas/desktop_window.py` |
| Жизненный цикл карты | `atlas/store.py`, `atlas/integrations/graphify/`, `atlas/enrichment_pipeline.py` |
| Новая языковая конструкция | `atlas/flow_languages/` и соответствующий `mods/language-*/` |
| Новые правила тестовой библиотеки | `mods/framework-*/`, [правила анализа](analysis-mods.md) |
| Документный формат | `atlas/documents/`, `mods/document-*/`, [контракт документов](document-maps.md) |
| Карточка или панель | `web/`, ближайший контроллер и его тест |
| Native-сборка или обновление | `packaging/`, [инструкция](../packaging/UPDATING.md) |

Объяснение сверено с картой и исходниками 21 октября 2026 года. Оно описывает
ответственности; фактическая поддержка каждой конструкции проверяется её тестами.
