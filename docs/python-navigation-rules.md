# Правила навигации по Python-проектам

## Области проекта

Включённый мод `language-python` ищет `pyproject.toml`, `setup.py`, `setup.cfg` рядом с индексированными исходниками. Манифест читается как обычный файл: setup.py, импорты, сборка и код проекта не выполняются. Ближайшая однозначная граница сохраняется как build-project; вложенные проекты не сливаются с родительским.

Если явных границ подпроектов нет, используются реальные папки. Общий префикс пакета и настроенные `sourceRootMarkers` определяют логические области: например `atlas`, `tests`, `scripts`, либо `src/app/api` и `src/app/services`. Файлы непосредственно в общей папке без манифеста получают область этой папки; плоский проект — область «Корень». Это `logical-area` с `confidence=folder-heuristic`, а не выдуманный пакет сборки. Исходные ID и связи сохраняются.

Правило принадлежит языковому моду (`logicalFolders: true`), не отдельной странице Atlas. Оно применяется при обновлении карты и одинаково доступно карте и MCP. Структура папок не доказывает архитектурную независимость или направление зависимостей.

## Точки входа

Отдельные библиотечные моды требуют `language-python`:

- `framework-fastapi`: HTTP-декораторы на импортированном FastAPI/APIRouter, локальный префикс роутера и буквальные методы/пути.
- `framework-fastmcp`: MCP tools, resources и prompts на импортированном FastMCP. Поддержаны SDK `mcp.server.fastmcp` и пакет `fastmcp`.

Каждый мод декларативно выбирает версионированную host strategy в `analysis.entrypointProviders`; пользовательский Python-код не подгружается как парсер. Контракт стратегий общий: вид входа, метка, реальный handlerNodeId, исходный файл/строка/хэш, владелец-мод и ограничения. Неоднозначное сопоставление не создаёт поддельный ID. Точки MCP имеют отдельный фильтр MCP в каталоге, инструменты различаются с ресурсами и prompts.

Обработчики определяются по точному объявлению AST и позиции графа. Учитываются импортные aliases, вложенные фабрики, типизированные app-параметры и передача известного app в точно разрешённую функцию регистрации (до трёх шагов). Shadowing и неизвестные объекты не превращаются в FastAPI/FastMCP только по имени переменной. Модули не импортируются и не запускаются. Пути чтения, объём, число файлов, AST и входов ограничены; ошибки/усечение/несопоставленные receivers видны в coverage.

Это статические объявления. Динамические имена и маршруты, фабрики с вычисляемым возвращаемым объектом, импортированные экземпляры приложений, `include_router` mount-префиксы, запуск фабрики, выбранный транспорт MCP, окружение и исполнение обработчиков не установлены. Локальный путь APIRouter не выдаётся за окончательный URL. CLI/main, Flask/Django и иные библиотеки потребуют собственных провайдеров.

## Как изучать Atlas

1. Включить `language-python`, затем `framework-fastapi` и `framework-fastmcp` по актуальным fingerprints; обновить карту один раз.
2. На уровне проектов выбрать логическую папку. В поиске выбрать «Точки входа» → HTTP API либо MCP.
3. Найти маршрут, имя инструмента или URI ресурса. Открыть обработчик или построить путь от него. Например HTTP `/api/projects/{project_id}/search-nodes` ведёт к HTTP-обработчику поиска; MCP `search_nodes` — к инструменту в `atlas/agent_mcp.py`. Это разные входы, даже если они используют общий API.
4. В деталях проверить sourceKind, тип операции, handler и неизвестные части. В MCP те же сведения находятся в `analysisFacts.entrypoints`, подробности — в `entrypointFacts`.

Каталог Python-входов читает факты снимка (`capturedOnly=true`) без повторного обхода исходников и инфраструктуры. Данные, изменённые после снимка, вступают в силу после следующего обновления. Это сохраняет доступность каталога при недоступной рабочей копии. Старые C#/инфраструктурные live-пути остаются совместимы; новый параметр API не включает их автоматически.
