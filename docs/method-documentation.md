# Чтение метода через документацию

В цепочке вызовов переключите «Режим чтения» со «Схема» на «Документация».
Для отдельного выбранного метода нажмите «Документация» в панели узла.
Назначение метода и его класса, входные параметры и результат берутся из
XML-документации или прилегающего обычного комментария. Внутренние комментарии
остаются возле соответствующей ветви.

Условия `if` читаются как «если значение больше…», «если значение отсутствует
(null)…», «иначе…». `switch` сохраняет варианты, общие тела и собственный `when`
каждой метки. Циклы читаются как «для каждого элемента…» или «повторять, пока…»;
`do` отдельно отмечает обязательное первое выполнение.

Условный оператор C# `условие ? значение : альтернатива` (`?:`) также образует
две ветви «Тогда» / «Иначе». Каждая сохраняет своё выражение, включая литералы,
`null` и `throw`; вложенные операторы показываются внутри соответствующей ветви.
Вызовы из условия не относятся к выбранной альтернативе. Эти же факты доступны
в MCP через `controlFlow` описания узла и цепочки вызовов (`kind: conditional`).
Операторы `?.`, `??` и nullable-типы не считаются тернарным ветвлением.

Описание метода и его execution path также возвращают `readabilityRecommendations`.
Длинный `return` (выражение от 1000 символов) или возврат с несколькими `?:` /
switch expressions получает рекомендацию `extract-return-result`: выделить
вычисление в типизированную локальную переменную и затем `return result;`.
Это эвристика читаемости, а не ошибка и не готовый autofix. При создании схемы
агент может добавить заметку на raw-ID метода; изменять исходник следует только
в разрешённой задаче, сохраняя типы, порядок, await и область действия.
Вложенные методы и lambda не относятся к возвратам caller. У ответа есть лимиты
и флаг усечения; отсутствие рекомендаций не доказывает качество кода.

Кнопка вызова открывает документацию его цели; возможные реализации помечены
явно. Список методов относится к текущему анализу цепочки. В DOM строится только
один выбранный метод. Переходы не раскрывают весь граф и не меняют масштаб.
«К схеме» возвращает карту с прежней камерой и раскрытыми узлами. Режим
сохраняется в URL через `reading=documentation`, вместе с корнем `path` и
выбранным `node`, и восстанавливается при перезагрузке и Back/Forward.

Исходные выражения и ссылки на строки доступны в раскрываемом «Исходник».
Читаемое описание не исполняет код, не выбирает DI-реализацию и не вычисляет
результат условия или число повторений. Сложное выражение остаётся точной
цитатой, если его смысл нельзя безопасно выразить поддержанным правилом.
Другие операции, включая присваивания и формулы, доступны в исходнике.

Данные берутся из существующего execution-path API: текущие C#-исходники и
связи сохранённого снимка. Ограничения анализа видны на странице. Условные
действия без сопоставленного arm не превращаются в безусловные шаги.
Неподдержанные переходы и вложенные функции обозначаются отдельно; этот режим
не заявляет полную трассу выполнения.

Для агентов правила написания автономных описаний и сборки сквозного текста
встроены в [skill Code Atlas](../skills/code-atlas/SKILL.md), раздел «Сквозная
документация из автономных описаний». Описание каждого метода объясняет его
собственное действие; контекст вызова и вложенность ветвей добавляются при
объяснении процесса. Эти правила направляют работу агента с исходниками:
текущий UI продолжает отображать фактические комментарии и поддержанные
конструкции, без автоматического переписывания текста агентом.


## Правила написания комментариев агентами

В skill, раздел «Формат и полнота документации при изменении кода», закреплены:
многострочные блоки описания, содержательные описания всех объявленных
параметров и параметров типов, результата, выходящих исключений с условиями,
существенных нюансов и примеров для неочевидного использования. Правила
применяются к новым и изменяемым методам в пределах задачи.

C# `summary` начинается и заканчивается на отдельных строках с `///`;
текст внутри также сохраняет `///`. Короткие теги параметров могут оставаться
однострочными. Дополнительные правила поведения помещаются в `remarks`,
подтверждённые исключения — в `exception`, примеры — в `example`/`code`.
Для Python, JSDoc/TSDoc, Javadoc/KDoc, Doxygen, Rust и Go skill задаёт родные
формы документации: чужие XML-теги не переносятся механически.

Основания для форматов: [XML-документация C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/documentation-comments),
[Python PEP 257](https://peps.python.org/pep-0257/),
[rustdoc](https://doc.rust-lang.org/rustdoc/how-to-write-documentation.html).
Многострочная форма — выбранное соглашение Atlas, включая допустимую PEP 257
форму docstring с текстом после открывающих кавычек на следующей строке.

Это инструкция агентам, а не автоматический форматтер или проверка полноты
контракта. Она не расширяет поддержку тегов в UI/парсерах и не меняет веса
code health. Наличие секции или примера не доказывает их правильность.
