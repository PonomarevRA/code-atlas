# Анализ покрытия условий

Страница `/coverage.html` показывает условия C#, найденные unit-тесты и Gherkin-сценарии. Кнопка **Покрытие тестами** на карте открывает выбранный метод и его цепочку вызовов. На странице можно перейти к анализу всего репозитория, отфильтровать `if`, `switch` или циклы и открыть исходник метода.

## Что является доказательством

Три слоя остаются раздельными:

- **Условия исходника** — статическая структура текущей рабочей копии: выражение, файл, строка, метод и цели проверки. Для `if` полезны оба результата, включая неявную сторону без `else`. Для `switch` полезны отдельные метки; для цикла — выполнение тела и выход. Это цели тестирования, а не результаты запуска.
- **Связи с тестами** — найденные атрибуты C# и сценарии `.feature`, возможные bindings и пути по сохранённому графу вызовов. Существование теста, его имя, параметры Theory или строки Examples не доказывают выполнение условия. Пропуск, объявленный в исходнике, сохраняется отдельно от неизвестного результата запуска.
- **Данные выполнения** — сведения из локального Cobertura XML с указанием источника. Если строки отчёта удаётся однозначно сопоставить условию, показываются счётчики инструментированных переходов этой строки. Они не устанавливают, какой конкретный тест выполнил ветвь, и не заменяют проверку всех логических подусловий составного выражения.

`unknown` означает недостаток данных. Оно не равно `uncovered`. Наличие line hits без branch counters не доказывает прохождение обеих сторон `if`. Устаревший, противоречивый или неоднозначный отчёт не превращается в подтверждённое покрытие. Цели проверки `true`/`false`/`case` остаются неизвестными без точного сопоставления отдельных переходов.

## Локальные отчёты

При анализе обнаруживаются поддерживаемые отчёты внутри выбранного репозитория. Можно явно указать до восьми путей относительно его корня. Приложение читает данные, не выполняет тесты или команды из проекта и не устанавливает зависимости. Чтение ограничено бюджетами; ограничения и пропуски видны на странице.

Время отчёта помогает выявить очевидно устаревшие данные, но не является доказательством совпадения сборки и текущего исходника. Для воспроизводимой проверки используйте отчёт той сборки, исходники которой открыты. Агрегированный Cobertura не даёт распределения покрытия по отдельным Gherkin-сценариям и unit-тестам.

Инвентарь ограничен 500 файлами и 32 МиБ исходников, 100 файлами Gherkin, 3000 методами, 10 000 условиями и 2000 объявлениями тестов. Цепочка ограничена 600 узлами и глубиной 30. Отчёт может занимать до 8 МиБ, все отчёты вместе — до 32 МиБ; JSON-ответ ограничен 8 МиБ. При исчерпании бюджета результат явно помечается частичным. Короткий список связанных тестов содержит до двух представителей с сохранением обоих видов тестов, если они найдены. Количество остальных связей и сокращение длинных путей указаны отдельно.

Разбор сценариев учитывает EN/RU заголовки и параметры Examples. Неподдержанные конструкции и неоднозначное разрешение шагов остаются ограничениями анализа. Python, JavaScript и другие языки не получают фиктивных условий C#.

## HTTP API

`POST /api/projects/{projectId}/test-coverage`

```json
{
  "snapshotId": "текущий snapshotId проекта",
  "nodeId": "необязательный raw ID метода",
  "reportPaths": ["TestResults/coverage.cobertura.xml"]
}
```

Без `nodeId` анализируется репозиторий. Без `reportPaths` используется ограниченное обнаружение отчётов. Снимок проверяется до и после анализа; изменение карты возвращает `409`. Два анализа могут работать одновременно; третий получает `429`. API не меняет опубликованный граф или исходники анализируемого проекта.

Ответ содержит отдельные `conditions`, `methods`, `tests`, `reports`, `summary`, `limits`, `truncation` и `warnings`. Текущие файлы не выдаются за неизменяемое содержимое снимка: `sourceKind` явно обозначает сочетание рабочей копии и сохранённого графа.

`sourceFacts` содержит хеш и время прочитанных файлов C#. Это происхождение текущего анализа, а не доказательство совпадения с содержимым сборки Cobertura. Ссылки на символы открывают текущую карту; обновление проекта может изменить доступность старого raw ID.

Источники форматов: [Gherkin reference](https://cucumber.io/docs/gherkin/reference/), [Coverlet](https://github.com/coverlet-coverage/coverlet).

## MCP: компактный анализ для агентов

`get_test_coverage` доступен в том же проектном stdio-подключении. Сначала получите текущие `snapshotId` и raw `nodeId` через `search_nodes`; затем запросите сводку:

```json
{"snapshotId":"из search_nodes","nodeId":"raw ID метода"}
```

`projectId` можно опустить только в подключении с `--project-id`. Без `nodeId` анализируется весь репозиторий. `section` принимает `summary`, `conditions` или `tests`. Списки фильтруются по `query`, `kind` (`if`, `switch`, `loop`), `runtimeStatus` и `testKind` (`unit`, `gherkin`). `testKind` у условий проверяет число всех найденных статических связей, даже когда в карточке показаны только два представителя.

```json
{
  "snapshotId":"из search_nodes",
  "nodeId":"raw ID метода",
  "section":"conditions",
  "query":"SelectContractsForQuotes",
  "kind":"if",
  "runtimeStatus":"unknown",
  "limit":1
}
```

Используйте возвращённый `pagination.nextOffset` и тот же `analysisId` для следующей страницы. `analysisId` связывает страницы с полным **ограниченным результатом текущего анализа**, включая найденные сценарии и сведения отчётов. Это не хеш всего проекта или сборки. При изменении данных продолжение отклоняется; начните с `offset:0`. Каждый запрос повторяет анализ — отдельного кэша сессии нет.

Для подробностей передайте полученный `conditionId` или `testId`. Неизвестный ID возвращает ошибку. `coverageUrl` открывает те же отчёты и фильтры в UI. Поиск не доказывает выполнение ветвей: без подходящего отчёта фильтр `uncovered` может вернуть пустой список при наличии `unknown` условий.

HTTP-таймаут MCP для этого анализа — 120 секунд: первый запрос установленной сборки может занимать больше времени. У клиента MCP должен быть достаточный таймаут ожидания. Повторяющиеся пути raw-узлов проверяются один раз внутри текущего анализа; фактическое чтение файла повторно проверяет границы и запрещает symlink. Исходники, AST и отчёты между запросами не кэшируются. Если ожидание истекло, сервер может продолжать работу; сообщение ошибки это указывает.

`limit` ограничен 40, `offset` — 100000. Текст ответа ограничен 30000 байт, полный MCP envelope с дублированными structured/text данными — 64000 байт. Сокращённые поля и записи указаны в `projection`; текущая страница может содержать меньше `limit` записей. Перемещайтесь по фактическому `nextOffset`. Сводка сохраняет ограничения исходного анализа; пагинация не превращает частичный инвентарь в полный. MCP не запускает тесты и не записывает данные в анализируемый проект.
