# Объявленные данные тестов

Atlas показывает статические объявления, а не результат запуска. Для тестового класса исходной точкой служит список тестов, принадлежащих точному `containerNodeId`. Вложенные и соседние классы не объединяются по имени файла.

## Как изучать тест

1. Откройте класс и выберите тест в обзоре справа.
2. В разделе «Данные и варианты» сравните именованные входы. У небольших Map сразу видны ключи; отсутствующий ключ, `null`, `""` и строка `"null"` различаются.
3. Перейдите к исходнику строки или откройте схему от теста. Выбор строки отмечает объявленный вариант, но не вычисляет условия или случайные значения.
4. Подготовка, очистка, инъекции и агрегаторы показаны отдельно. Наличие callback не гарантирует выполнение или порядок раннера.

Проверены `OrderTests`: 36 объявлений; MethodSource — 3 строки ClientId; ValueSource — 1/10/30; CsvSource — 3 пары валют; EnumSource — 8 периодов. Это не число фактически выполненных сценариев.

## Контракт снимка

Java-парсер сохраняет имена/типы параметров и точного владельца. Мод JUnit выбирает проверенную стратегию `datasetStrategy`. Факты фиксируются при обновлении карты; просмотр не загружает код мода из анализируемого проекта. После обновления пакета проверьте его активацию: новый отпечаток требует включения проверенной версии перед перестроением карты.

- Тест: `handlerNodeIds`, `containerNodeId`, `parameters`, `context`, declared/runtime status.
- Источник: стабильный `id`, `strategy`, `nodeIds`, `composition`, `completeness`, `declaredRowCount`, `rowsTruncated`, `bindingStatus` и причина неизвестного.
- Строка: стабильные `id/index`, исходное выражение, source location/hash, значения и именованные `bindings`.
- Значение: отдельные kind для literal/expression/missing/null/map; неизвестные вычисления не превращаются в фактические значения.
- Связь `uses_test_data`: тест → существующий узел провайдера или enum, с доказательством исходника. Она не считается вызовом или порядком исполнения.

Обзор класса и поиск используют компактные summaries без строк. Большие детали доступны через один контракт HTTP/MCP:

`GET /api/projects/{id}/test-datasets?snapshotId=…&nodeId=…`

Первый запрос возвращает источники. Передайте выбранный `sourceId`, затем возвращённый `nextCursor`. MCP-инструмент `get_test_data` принимает те же аргументы. Курсор закреплён за снимком, тестом и источником; устаревший курсор отклоняется. Ответ до 48 000 UTF-8 байт, 1–30 строк; UI запрашивает 20. Строка, не помещающаяся целиком, даёт явную ошибку 413 вместо усечения ID или пропуска строки.

## Поддержка и ограничения

| Стратегия | Захватываемые факты |
| --- | --- |
| `junit-single-values-v1` | Один поддержанный массив ValueSource; одна ячейка на строку |
| `junit-literal-provider-v1` | Однозначный метод; единственный literal `Stream.of(Arguments.of(...))`; ограниченная структура `Map.of` |
| `junit-positional-csv-v1` | Literal строки; delimiter/delimiterString, quoteCharacter, trim, emptyValue и nullValues |
| `junit-enum-constants-v1` | Однозначное объявление/import enum; literal names и INCLUDE/EXCLUDE |
| `resource-reference-v1` / `unresolved-v1` | Объявление и причина отсутствия вычисленных строк |

Сохраняется до 30 строк источника. `nextCursor=null` означает конец захваченных строк, а не полноту генератора: проверяйте `captureTruncated` и `completeness`. Несколько источников не перемножаются. Неподдержанные CSV text blocks/headers/options, пересекающиеся emptyValue/nullValues, regex-фильтры enum, перегрузки, вычисляемые провайдеры, конвертеры и неоднозначное наследование остаются неизвестными с исходным выражением и причиной. Таблица показывает исходные CSV-ячейки, а не результат преобразования в тип параметра.

Фабрика и представление общие; перечисленные стратегии реализуют JUnit. Старые факты других фреймворков остаются доступными в прежнем виде, без придуманных именованных привязок. Ресурсы fixture не исполняются. Смысл HTTP/SQL/assertions изучается по исходнику и схеме; автоматическая интерпретация всех библиотек отдельными адаптерами остаётся следующим расширением.

Захваченные тесты открываются независимо от медленного поиска инфраструктуры. HTTP/Kafka/Rabbit добавляются вторым запросом; ошибка не удаляет тесты и не выдаётся за нулевое количество других входов. Поиск и повтор остаются доступны.
