# Поля и методы в общем снимке Atlas

Общий снимок, карты и MCP сохраняют поля, свойства, константы и методы без фильтра по public/private/protected. `memberFacts` описывает объявление и языковую видимость, `fieldFacts` — тип и захваченную документацию, `dataFacts` — исходный инициализатор и ограниченные пары словаря. Источник этих фактов — `snapshot-captured-source`; чтение не обновляет снимок и не исполняет проект.

`method`, `field` и `property` — принадлежность классу. `reads` и `writes` — лексическое обращение к полю. Простое присваивание записывает поле; `+=`/`++` читает и записывает. Запись элемента коллекции читает её receiver и не означает замену самого поля. В карте локального тела одно поле сохраняет обе связи. Словари экземпляра раскрываются тем же деревом пар, что статические словари. Поле без инициализатора остаётся объявлением с неизвестным значением.

C# использует существующую модель исходника. Дополнительный ограниченный AST-проход поддерживает Java, Python, JavaScript/TypeScript, Go, C++, Kotlin, PHP, Rust и Swift. Он сохраняет исходные ID и все связи Graphify, дополняя недостающие объявления собственными ID. Python подчёркивания и uppercase — соглашения об именах, Go показывает экспортируемость из пакета. `readonly`/`final` не доказывает неизменяемость содержимого объекта. Подробный анализ тела метода для дополнительных языков остаётся отдельным ограничением; захваченная сигнатура не выдаётся за полный control-flow.

Неизвестные receiver, динамические и наследованные обращения, другие языки и сложные формы объявлений не восстанавливаются предположениями. Пары и фабрики — выражения исходника, а не вычисленные значения. Метаданные `memberGraph`/`sourceStructure`, предупреждения и `truncated` показывают пределы разбора. Весь проход ограничен файлами, байтами, AST, добавленными узлами/рёбрами и объёмом инициализаторов. Поиск кандидата Graphify индексирован по файлу/имени, без сканирования всего файла для каждого объявления.

`get_node` возвращает захваченные факты; поиск и соседство сразу показывают видимость и до трёх пар. Ответы ограничены 64 КБ. Печатный Graphify MCP имеет дополнительный предел атрибутов и сортирует ключи; компактные `atlas.0.member`, `atlas.1.data`, `atlas.2.comment` сохраняют видимость, одну пару и начало комментария перед обрезанием; для полного захваченного значения используйте Atlas `get_node`. Дистрибутивный skill `skills/code-atlas/SKILL.md` объясняет эти границы агентам.

Проверки: `tests/test_member_graph.py` использует реальные установленные грамматики, настоящий Graphify и stdio MCP. Дополнительно проверяются затенение, отложенные lambda, несколько инициализаторов, перегрузки, forward receiver Go и сохранение исходных данных после удаления исходника. `tests/test_inline_method_body.mjs` проверяет экземплярный словарь и обе связи одного поля.

## Rust

Rust также поддерживает оценки сложности и документации: `if`, `match` с guards, `for`/`while`/`loop` и `?`. Closure, локальные функции и отложенные блоки не добавляются к сложности вызывающего метода. Методы разных `impl`/трейтов/модулей имеют разные health identity. Rustdoc перед `#[inline]`/`#[cfg]` сохраняет принадлежность функции; внутренние `//!`/`/*!` не подменяют её описание. `Cargo.toml`, присутствующий в снимке, задаёт границу проекта; вложенный crate имеет приоритет. Макросы не расширяются и дают частичную оценку. Факты доступны через общий поиск и MCP; полная пошаговая схема Rust-тела пока не поддержана.
