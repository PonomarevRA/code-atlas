# Работа с картой

1. Выберите сохранённый репозиторий, локальную папку или загрузите репозиторий Git.
2. Для реализации фичи используйте раздел **Код**. Поиск имени/пути не скрывает
   остальные узлы. Каталог HTTP, MCP, CLI, сообщений и тестов помогает найти доступную точку входа.
   Набор определяется языком и активными framework-модами; неполнота подписывается.
3. Выберите обработчик: доступны описание, статический путь вызовов и текущий
   исходник. Строка снимка могла сместиться в рабочей копии.
4. **Архитектура** показывает внешние зависимости с двумя масштабами: репозитории
   и проекты/логические области. При отсутствии build-манифеста языковой мод
   может предложить группировку по папкам; это эвристика, а не архитектурный контракт. У связи доступны основания из кода/конфигурации.
5. **Группы** — дополнительное исследование сообществ, не архитектурный контракт.

Применяйте фильтры по задаче; regex-поиск подсвечивает совпадения, не удаляя
контекст. Подключённые репозитории позволяют рассматривать общие зависимости.
Общий хост не доказывает, что несколько проектов обращаются к одному сервису.

## Оценки карточек

Выберите показатель в меню «Оценка карточек» и откройте карточку метода,
чтобы увидеть её замечания. Формулы и пример сравнения до и после правок
описаны в разделе [Оценки и здоровье кода](Code-Health.md).

## Чтение файлов и HTML

В разделе **Код → файлы** карточки собраны по папкам. Для файла без цепочки
вызовов символы идут в порядке строк. В HTML с захваченным деревом отступ и
подпись «Внутри» показывают родительский элемент. При фильтрации глубина
сохраняется, даже когда родитель на другой странице.

Выберите HTML-файл или элемент и откройте **Статический эскиз** в инспекторе.
Atlas строит схему из фактов снимка и коротких текстовых подписей. Проектные
стили, скрипты, обработчики, формы и ресурсы страницы в схеме не запускаются.
Снимок старой версии может показывать только структуру. Чтобы получить подписи
из текста элементов, обновите карту с включённым HTML-модом.

## Как растёт архитектура

Переходы по объявлениям в разделе **Код** сохраняют найденные инфраструктурные
операции для текущего снимка. В **Архитектуре** раскрывайте блоки Kafka, RabbitMQ
и БД, чтобы увидеть топики, очереди и таблицы. Внешние HTTP-системы добавляются
по известным вызовам с буквальным адресом. Выберите связь, чтобы прочитать
основание и перейти к исходнику.

Конфигурация, статически найденный вызов и наблюдение исполнения — разные
основания. Если конкретное соединение или брокер не установлен, блок показывает
неизвестную привязку. Основные узлы и закрепления остаются на карте; новая
детализация не требует повторного размещения уже показанных карточек.

Экспорт **Structurizr DSL** сохраняет семантическую модель для architecture as code.
Экспорт **Atlas JSON** дополнительно сохраняет доказательства, закрепления и
координаты. Выгружается текущая раскрытая модель с учётом фильтров, включая её
страницы. DSL использует автоматическую раскладку: пиксельное положение карточек
не переносится. Это статическая модель исследованной области, а не полная схема
развёртывания или запись исполнения.

Сохранённое представление агента содержит выбранные raw-узлы, исходные связи,
проектные блоки и явно обозначенные авторские пояснения. Это неизменяемый снимок
с локальной ссылкой и PNG; исправление создаёт новый снимок.

## Что добавляет мод

Языковые, build и framework-моды объявляют входные файлы, правила проектов, точки входа и тестовые данные. Wiki установленных модов появляются под соответствующим разделом руководства. Откройте страницу профиля, чтобы проверить его точные стратегии, пример и границы. Чтение документации не активирует пакет. Если нужного профиля нет в каталоге, отсутствие его страницы не доказывает отсутствие языка в проекте.

Сохраняйте различие `id` и `label`: подпись удобна для поиска, связи и продолжения ссылаются на конкретный ID снимка. Для большого окружения агент может читать страницы связей; завершённая страница ещё не означает завершённый обход.
