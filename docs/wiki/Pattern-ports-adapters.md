## Задача

Правило знает конкретный протокол или драйвер и не запускается отдельно от внешней системы.

## Когда применять

- Папка с I/O должна поддерживать другой backend.
- Один use case вызывается через несколько транспортов.

## Когда не применять

- Интерфейс существует только ради единственного тривиального вызова и ничего не изолирует.

## Граница класса или папки

Папка приложения содержит порты и use cases; адаптеры находятся на внешней границе.

## Ответственность

- Определить нужную приложению операцию.
- Перевести внешний формат в проверенные значения.

## Публичный контракт

Reader.read() -> list[int]; недоступность источника представлена явной ошибкой адаптера.

## Зависимости

- Ядро знает контракт Reader, не SqlReader.
- Composition root выбирает адаптер.

## Состояние и время жизни

Пул соединений и освобождение принадлежат адаптеру; use case не закрывает чужой ресурс.

## Ошибки

- Адаптер преобразует техническую ошибку в договорённый результат или исключение.

## Пример

```python
from typing import Protocol

class Reader(Protocol):
    def read(self) -> list[int]: ...

def calculate(reader: Reader) -> int:
    """Суммирует значения из явно переданного порта."""
    return sum(reader.read())
```

Требуемый интерфейс виден у вызывающего кода и заменяется тестовым reader.

## Контрпример

```python
def calculate():
    from product_database import global_client
    return sum(global_client.query_all())
```

Глобальная зависимость скрыта и связана с конкретным драйвером.

## Как внедрять

- Опишите минимальную операцию, нужную use case.
- Перенесите создание драйвера в composition root.

## Ограничения

- Protocol описывает структуру типов, но не гарантирует корректное поведение.

## Что проверять

- Запустить use case с простым test adapter.
- Проверить контракт реального адаптера отдельно.

## Альтернативы

- Передать callable вместо класса, если нужна одна операция.

## Как писать код

- Описание метода объясняет вход, результат и существенные ошибки; комментарий ветви объясняет причину.
- Используйте ясные локальные этапы и ранние выходы; новый класс или интерфейс нужен только для самостоятельной ответственности.
