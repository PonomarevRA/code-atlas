# Совместимое обновление ядра MCP проекта

Это проектный рецепт для проверки на конкретном runtime. В справочнике он имеет статус draft; общий механизм обновления приложения ещё требует квалификации. Ниже отдельно указан узкий реализованный source-пилот.

## Разделить ответственность

Стабильный MCP facade владеет транспортом и публичным контрактом tools. Прикладное ядро выполняет use cases и не зависит от MCP SDK. Lifecycle coordinator готовит поколение, проверяет совместимость и переключает новые вызовы. Хранилище сохраняет результаты и identity заданий/курсоров.

Ориентир: клиент → стабильный facade → согласованная граница вызова → поколение ядра → совместимое хранилище. Отдельный proxy-сервис нужен только при доказанной необходимости. В Atlas уже существует граница stdio MCP → LoopbackTransport → локальный HTTP API; сама по себе она ещё не доказывает бесшовность обновления.

## Что считается совместимостью

Неизменных имён tools недостаточно. Проверяются input/output schemas, nullability, смысл и единицы полей, ошибки, scope/auth, side effects, pagination, handles, capabilities и поддерживаемый protocol profile. Равенство schema hash не доказывает одинаковое поведение.

По [MCP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) stdio связан с запущенным клиентом процессом. В [Streamable HTTP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) protocol-level sessions удалены. Legacy initialize/session и современный HTTP профиль нельзя описывать одним безусловным шаблоном. Фактические SDK и negotiated version проверяются перед внедрением.

## Подготовить переключение

1. Снимите contract manifest и storage/handle compatibility текущего поколения.
2. Подготовьте N+1 из неизменяемого артефакта и проверьте readiness до switch.
3. Закрепите уже принятые вызовы за N; новые направляйте в N+1 только после принятия кандидата.
4. Сохраняйте маршруты progress, cancellation, jobs и cursors до завершения владельцев. Ограничьте время drain и определите результат превышения срока.
5. Не переисполняйте мутации после timeout без доказанной идемпотентности. Потеря ответа не означает отсутствие эффекта.
6. Освободите старое поколение после завершения владельцев и проверки хранения.

Логическое переключение маршрута отличается от физической замены executable. Активные frozen readers могут повторно читать старые архивные диапазоны. Поэтому rename файла и возврат старого binary не являются универсальным безопасным rollback; применяются отдельные правила упаковки и публикации.

## Доказать результат

Подключите клиента до обновления. Проверьте вызовы до, во время и после него, сохранение client-side channel/host PID и фактическую смену core identity. Длительный вызов должен завершиться в своём поколении; отмена, cursor и повтор после timeout не должны смешивать результаты или дублировать запись.

Добавьте отрицательные случаи: schema mismatch, неготовый candidate, несовместимый storage, истёкший lease и два клиента одновременно. Если изменился сам facade или tool surface, отдельно решите вопрос discovery/reconnect. Добавление инструментов этого справочника — начальное расширение surface, а не неизменный core-only update.

## Реализованный source-пилот Atlas

`atlas/core_generations` заменяет только чистое вычисление module projection. Стабильный host сохраняет HTTP, MCP, ProjectStore, jobs и cursors. Подготовка проверяет bundle/protocol/semantics/runtime profile; новые вызовы переключаются атомарно, старый вызов закрепляется за своим worker. Есть ограничение двух поколений, по одному активному вычислению на поколение, bounded drain и принудительное завершение. Мутации автоматически не повторяются.

`tests/test_core_generations_mcp.py` проверяет настоящего stdio SDK клиента с одним initialize, неизменными дескрипторами tools, различными source hash/PID N и N+1, завершением старого вызова, отказом несовместимому кандидату и сохранением байтов fixture. Unit-проверки отдельно покрывают отмену и границы процесса. Это не доказательство обновления stable host, frozen executable, native-установки или пользовательского активного подключения. По умолчанию host использует прежний inline compute; worker coordinator передаётся явно доверенной композицией.
