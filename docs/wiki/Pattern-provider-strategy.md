# Стратегия и реестр провайдеров

Заменяемый алгоритм выбирается по явному ID через реестр с одинаковым контрактом входа и результата.

## Задача

Новые алгоритмы добавляются ветвями в UI, а общие веса и исходные данные изменяются неявно.

## Когда применять

- Несколько реализаций одной измеримой задачи.
- Нужен честный baseline с фиксированными параметрами.

## Когда не применять

- Варианты решают разные задачи с несовместимыми входами или objective.

## Граница класса или папки

Класс провайдера или папка алгоритма; реестр только разрешает ID, не вычисляет результат.

## Ответственность

- Валидировать ID.
- Сохранить параметры и provenance конкретного запуска.

## Публичный контракт

choose(provider_id)(values) -> результат; неизвестный ID — явная ошибка.

## Зависимости

- Алгоритмы не импортируют UI.
- Реестр не изменяет raw graph.

## Состояние и время жизни

Параметры и seed принадлежат запуску, а не изменяемому глобальному singleton.

## Ошибки

- Неизвестный provider_id отклоняется, а не заменяется default молча.

## Пример

```python
def choose(identifier):
    """Возвращает только явно разрешённый алгоритм."""
    providers = {"sum": sum, "maximum": max}
    if identifier not in providers:
        raise ValueError("Unknown provider")
    return providers[identifier]
```

Реестр ограничен и неизвестное значение не подменяет семантику.

## Контрпример

```python
def choose(identifier):
    return eval(identifier)
```

Выполнение введённой строки не является безопасным выбором стратегии.

## Как внедрять

- Согласуйте общий контракт.
- Зарегистрируйте проверенную реализацию и её параметры.

## Ограничения

- Усреднение разных objective не создаёт справедливого сравнения.

## Что проверять

- Неизвестный ID отклоняется.
- Один input не мутирует между сравниваемыми провайдерами.

## Альтернативы

- Один обычный вызов, пока альтернатив нет.

## Как писать код

- Описание метода объясняет вход, результат и существенные ошибки; комментарий ветви объясняет причину.
- Используйте ясные локальные этапы и ранние выходы; новый класс или интерфейс нужен только для самостоятельной ответственности.
