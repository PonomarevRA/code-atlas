# Идемпотентная команда и безопасный retry

Повтор команды использует устойчивый ключ намерения и согласованную дедупликацию, а не повторяет эффект после timeout.

ID: `idempotent-command` · версия: `1.0.0` · статус карточки: **draft**.

Content hash: `310f3de865f54ad874537fbc4bd517cee8be2cb4ee4da6511d0c5f09e23fd406`.

Catalog version: `3b1765c0fa5449368237cddb8631362e34807809260037307e3e8e95780f3fa5`.

Квалификация применения в проекте: **not-assessed**. Чтение карточки не подтверждает внедрение.

## Задача

Потерянный ответ заставляет клиента повторить уже выполненную запись.

## Когда применять

- Команда с побочным эффектом может повторно прийти после сбоя связи.
- Есть долговечный журнал или транзакционная дедупликация.

## Когда не применять

- Нельзя отличить новый запрос от повтора с тем же ключом.

## Граница класса или папки

Папка command handler/store атомарно связывает intent, результат и эффект.

## Ответственность

- Проверить совпадение payload для ключа.
- Вернуть сохранённый результат либо статус операции.

## Публичный контракт

Ключ повторного намерения не меняется при retry; иной payload с тем же ключом отклоняется.

## Зависимости

- Transport не делает blind replay.
- Storage обеспечивает нужную атомарность.

## Состояние и время жизни

Дедупликация сохраняется дольше времени возможного повтора; один RAM dict этого не гарантирует.

## Ошибки

- Timeout означает неизвестный исход, а не гарантированный отказ команды.

## Пример

```python
def retry_decision(operation_status):
    """Разрешает повтор только при доказанном непринятии."""
    if operation_status == "not-accepted":
        return "retry-same-key"
    return "query-status"
```

Решение учитывает известность принятия; сама транзакционная дедупликация должна находиться в storage.

## Контрпример

```python
def on_timeout(send):
    return send()
```

Timeout не исключает уже совершённый эффект.

## Как внедрять

- Уточните семантику одинакового intent.
- Сделайте запись результата и эффекта согласованной.

## Ограничения

- Не обещает exactly-once без доказанного storage protocol.

## Что проверять

- Потерять ответ после commit и повторить тот же ключ.
- Проверить отказ при changed payload и том же ключе.

## Альтернативы

- Запрашивать статус и требовать ручное решение, если безопасный повтор невозможен.

## Как писать код

- Описание метода объясняет вход, результат и существенные ошибки; комментарий ветви объясняет причину.
- Используйте ясные локальные этапы и ранние выходы; новый класс или интерфейс нужен только для самостоятельной ответственности.
