# Владение ресурсами и ограничение работы

Один владелец управляет получением и освобождением ресурса; очередь, время и отмена имеют явные пределы.

## Задача

Ресурс теряется при исключении, а фоновые работы переживают владельца без политики завершения.

## Когда применять

- Файлы, HTTP-клиенты, locks или worker tasks имеют lifetime.
- Сервису нужны bounded concurrency и отмена.

## Когда не применять

- Функция работает только с переданными значениями без ресурсов.

## Граница класса или папки

Класс контекста или папка lifecycle с одним владельцем; consumers не закрывают общий пул.

## Ответственность

- Вызвать освобождение ресурса на happy и error paths; отдельно определить исход при ошибке cleanup.
- Ограничить число одновременно принятых задач.

## Публичный контракт

При выходе из closing вызывается close(). Успешное освобождение зависит от ресурса; ошибка close() может стать основной вместо ошибки чтения.

## Зависимости

- Вычисления получают ресурс через порт.

## Состояние и время жизни

Владелец lifetime известен: request, task или service; срок не расширяется скрыто.

## Ошибки

- Отмена не превращается в повторное выполнение. Если close() выбрасывает исключение, оно становится основным; исходная ошибка чтения может остаться в __context__. Политика ошибок cleanup должна быть явной.

## Пример

```python
from contextlib import closing

def read_one(open_resource):
    """Читает ресурс и вызывает close; ошибка close может перекрыть read."""
    with closing(open_resource()) as resource:
        return resource.read()
```

Контекст вызывает close() и после ошибки чтения. Это гарантирует попытку cleanup, а не успешное закрытие или сохранение исходного исключения как основного.

## Контрпример

```python
def read_one(open_resource):
    resource = open_resource()
    value = resource.read()
    resource.close()
    return value
```

Исключение до close оставляет ресурс открытым.

## Как внедрять

- Определите владельца и срок.
- Вынесите acquire/release в контекст или явный try/finally.

## Ограничения

- Количество записей в кеше не является точным ограничением RSS.

## Что проверять

- Проверить исключение до завершения чтения.
- Проверить отмену, timeout и ограничение очереди.
- Проверить ошибку close() после ошибки read() и согласованный приоритет исключений.

## Альтернативы

- Использовать стандартный with у самого ресурса.

## Как писать код

- Описание метода объясняет вход, результат и существенные ошибки; комментарий ветви объясняет причину.
- Используйте ясные локальные этапы и ранние выходы; новый класс или интерфейс нужен только для самостоятельной ответственности.
