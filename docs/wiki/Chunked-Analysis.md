# Чанки, хранение и догрузка анализа

Atlas разделяет три задачи: извлечение фактов о проекте, сохранение ревизии и выдачу выбранных подробностей агенту. У этих задач разные чанки и лимиты.

## Как проходит Graphify

Новая сборка делит выбранные Graphify исходники на пакеты целых файлов: по умолчанию не более 32 файлов и с целевым объёмом 2 МиБ. Один более крупный файл остаётся целым и отмечается отдельно. Для каждого пакета сохраняется исходный корень проекта: перенос файлов в новые корни изменил бы относительные пути и идентификаторы.

Сначала Graphify извлекает пакеты. Затем его штатный общий проход разрешает связи по всему живому корпусу. Atlas использует промежуточные факты самого провайдера; готовые JSON отдельных пакетов не склеиваются по похожим именам методов. Глобальные проходы модов сохраняют свой общий контекст и порядок; локальное извлечение полей и атрибутов планируется пакетами без сброса общего бюджета.

Текущий протокол закреплён за Graphify 0.9.85. Python и C# могут переиспользовать проверенные локальные результаты между сборками. Изменение файла требует нового извлечения этого файла, а изменение известной конфигурации или состава файлов инвалидирует соответствующий контекст. TypeScript/JavaScript и непроверенные профили не получают обещания такого переиспользования; XAML заново учитывает соседние исходники.

Размер пакета ограничивает задание, а не память общего индекса Graphify. Полный контекст разрешения связей остаётся общепроектным. Тёплый кэш не гарантирует ускорения всей сборки: остаются проверки, чтение кэша и общий проход.

## Как сохраняется снимок

Канонический `atlas-graph.json` новой ревизии — небольшой manifest, то есть список проверяемых ссылок на сжатые объекты. Неизменившиеся объекты используются следующими снимками повторно. Хэши и пределы распаковки проверяются при чтении. Прежние JSON-снимки продолжают читаться.

Внутри объектов повторяющиеся концы рёбер могут храниться через локальные числовые индексы. Общие сведения проекта также сохраняются один раз. API восстанавливает исходные строковые ID, значения, порядок и параллельные связи. Числовой индекс не становится новым публичным ID символа.

Исходный результат Graphify сохраняется отдельно; совместимая MCP-проекция создаётся по запросу. Manifest и кэш не дают разрешения автоматически удалить историю или ранее выданные пути. Сжатие уменьшает диск; полная распаковка может стоить больше времени, чем чтение обычного JSON.

## ID и название узла

`id` обозначает узел в графе, `label` — подпись для человека. Например, `atlas_integrations_graphify_adapter_build_graph` и `build_graph()`. Связи используют ID. Graphify строит ID из пути и частей имени по правилам языка, затем нормализует строку; это не хэш тела метода и не обещание полной уникальной сигнатуры перегрузки.

Для связывания пакетов нужны общий корень, проверенная идентичность символов и основания рёбер. Совпадение `label` не доказывает вызов или выбор реализации.

## Продолжение через MCP

Если `get_neighbors` вернул `nextRef`, передайте его как `cursor` с теми же проектом, `snapshotId`, `nodeId` и направлением. Одна страница содержит не более 120 рёбер и 64000 UTF-8 байт. `nextRef: null` означает конец списка; повторные связи и self-loop сохраняются.

Для повторного чтения синтаксиса откройте `open_analysis_context`, передавайте полученный `contextId` в `get_method_flow_chunk` и `get_analysis_section` и после работы вызовите `close_analysis_context`. Успешное полезное чтение продлевает жизнь рабочего RAM-кэша до 20 минут бездействия. Закрытие не удаляет постоянные снимки.

`get_analysis_section` раскрывает разделы описания, которые не поместились в общий ответ: `methodFlow`, `documentation`, `calls`, `controlFlow`, `parameterFacts`. `items[].ref` раскрывает элемент, `nextRef` продолжает страницу через `sectionRef`. Описания пересчитываются: изменение соседнего handler или конфигурации может изменить факты при неизменном теле выбранного метода. Старое продолжение в таком случае отклоняется.

Пагинация не расширяет возможности анализатора. Усечения, unsupported и UNKNOWN остаются явными. AST-страница имеет `analysisKind: syntax-outline` и `flowStatus: not-computed`: синтаксическое дерево не является трассировкой исполнения.
