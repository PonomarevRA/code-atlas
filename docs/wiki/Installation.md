# Установка

## Из исходников

Откройте терминал в корне полученного репозитория. Нужен 64-битный Python
3.12 или 3.13; на Apple Silicon предпочтителен ARM64. Первичная установка
пакетов требует сети либо подготовленного wheelhouse.

macOS/Linux:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m atlas.cli --open
```

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m atlas.cli --open
```

Откройте http://127.0.0.1:8765. Остановить сервер — Ctrl+C.
Каталоги .venv, wheelhouse и dist не поставляются с обычным Git checkout.
Для отдельного окна установите packaging/requirements-desktop.txt в это
окружение и используйте --desktop.

## Готовый native-пакет

Для целевой ОС нужен её собственный пакет: macOS .app, Windows onedir с .exe,
Linux onedir с исполняемым файлом. Python, Graphify, грамматики и зависимости
включены в пакет. Git требуется отдельно только для Git clone и сравнения ревизий.
Если готовый пакет не предоставлен, используйте исходники или соберите его
по странице [Сборка и публикация](Development-and-Releases.md).

## macOS

В распакованном пакете запустите `sh install-macos.sh "Code Atlas.app"`.
В исходном репозитории этот установщик находится в packaging/.
Пользовательская установка не требует администратора. Не подменяйте приложение
во время выполняющейся индексации. При запуске пакета без аргументов открывается отдельное окно Atlas. Для каждой
архитектуры нужен совместимый пакет; результат проверки одной сборки не
подтверждает работу другой архитектуры.

## Windows и Linux

В native-пакете используйте `./install-windows.ps1 -Source ./CodeAtlas` или
`sh install-linux.sh ./CodeAtlas` соответственно. Каталог onedir переносится целиком;
одного .exe/бинарника недостаточно. Пакеты неподписаны: этот исходный проект не
содержит сертификатов Apple/Microsoft и не выполняет notarization.
Windows требует установленного WebView2 Runtime. Linux desktop использует
QtWebEngine и системные GUI-библиотеки. Нативные Windows/Linux release-прогоны
в текущей локальной проверке не выполнялись.

Если порт занят, остановите предыдущий Code Atlas либо запустите новый с
`--port 8766 --open`. Два процесса не могут одновременно владеть одной базой.
[Данные и обновления](Data-and-Updates.md) описывает перенос прежней .atlas.

Из CLI используйте `--desktop` для отдельного окна, `--open` для браузера
и `--no-open` для фонового сервера. Без выбора режима CLI открывает браузер
после готовности HTTP-сервера; запуск frozen-пакета без аргументов выбирает
`--desktop`. В окне есть команда открытия текущей карты в браузере.
Служебные команды экспорта MCP, миграции, резервного копирования и `--version`
браузер не открывают.

## Повторное обновление

Закройте Atlas. Из корня подготовленного репозитория выполните
`sh packaging/update-local.sh --build` (macOS/Linux) или
`.\packaging\update-local.ps1 -Build` (Windows). Без параметра сборки устанавливается
готовый dist. На Apple Silicon по умолчанию выбирается ARM64 даже под Rosetta.
Совместимое обновление не копирует и не архивирует отдельный каталог данных.
[Данные и обновления](Data-and-Updates.md).

## Если Graphify не может разобрать SQL

Сообщение `tree_sitter_sql not installed` означает отсутствие SQL-грамматики
в окружении, которое выполняет анализ. В текущем `requirements.lock` закреплён
`tree-sitter-sql==0.3.11`; сборка native-пакета проверяет импорт и разбор SQL
до упаковки. Для запуска из исходников обновите зависимости командой установки
выше. Для готового приложения установите обновлённый пакет Atlas: установка
пакета в Python редактора не меняет встроенный runtime приложения.

После исправления запустите **«Перестроить»** для нужной карты и проверьте
путь проекта и новое задание. Прежний снимок другого checkout не подтверждает
успешный анализ текущих исходников. Ошибка конкретного файла при наличии
грамматики требует отдельной диагностики по журналу задания.
