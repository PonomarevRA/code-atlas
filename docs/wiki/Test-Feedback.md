# Контекст ошибок тестов для агента

`prepare_test_feedback` читает переданный JUnit XML и подготавливает ограниченный пакет ошибок со ссылками на сохранённые исходные факты. Инструмент не запускает тесты или модель и не изменяет проект.

Сначала получите актуальные `projectId` и `snapshotId`. Затем передайте `reportId`, текст `junitXml` и, если они известны из источника отчёта, `reportedSnapshotId` и `reportedBuildId`. Не заполняйте неизвестную идентичность текущим снимком просто ради совпадения. Эти поля остаются заявлениями отправителя, а не подтверждением происхождения CI.

```xml
<testsuite>
  <testcase name="Example" file="tests/example.py" line="12">
    <failure message="Expected result differs">Reported stack trace</failure>
  </testcase>
</testsuite>
```

Ответ различает сообщённый результат теста, статический кандидат исходника и неизвестную runtime-привязку. Даже при совпадении пути, строки и хеша `executionVerified` остаётся `false`. Неоднозначные имена, дубликаты, устаревшие версии и неизвестные хеши не превращаются в подтверждённую связь.

## Ограничения импорта

Поддерживается UTF-8 XML без DTD и сущностей. Парсер ограничивает байты, глубину, число узлов, testcase и длину диагностик; системный вывод исключён. MCP принимает до 65 536 символов XML, HTTP — до 500 000 с дополнительным общим лимитом тела и парсера. Передавайте меньший отчёт при превышении бюджета.

Первый профиль принимает testcase только внутри дерева testsuite/testsuites, непосредственно под testsuite. Разметка testcase внутри логов или properties отклоняется. Неинтерпретируемые атрибуты результата status/result дают unknown, а не passed. Для обычного testcase без этих атрибутов отсутствие failure/error/skipped означает только сообщённое прохождение согласно этому профилю.

В пакете не более 20 записей failure/error/unknown и 64 000 UTF-8 байтов. `summary` считает реальные testcase, а не атрибут `tests` заголовка. `truncated` означает, что детали или записи не поместились. Отсутствие результатов не означает успешный запуск.

Общие формы credentials маскируются; это не полное обнаружение секретов. Сохраняйте собственные правила обращения с диагностикой.

## Повторное использование анализа

Для чтения AST по-прежнему используется существующий `AnalysisContexts`. Контекст связан с проектом, снимком и настройками; идентичность парсера и исходного содержимого входит в ключ чтения. Несовместимая область и истёкший контекст отклоняются. RAM-квоты исходного JSON и AST не являются измеренным пределом RSS процесса.
