# Версионированные DTO и ошибки

Сохраняйте смысл полей, nullability, единицы и ошибки; номер версии дополняет проверки совместимости.

## Задача

Те же имена API начинают принимать и возвращать другой смысл без предупреждения потребителя.

## Когда применять

- DTO, tools, курсоры или результат читаются разными версиями клиентов.
- Схема меняется независимо от вычислительного ядра.

## Когда не применять

- Значение живёт только внутри одной функции и не пересекает границу.

## Граница класса или папки

Папка контрактов независима от транспорта и алгоритмов; адаптер переводит DTO в use case.

## Ответственность

- Объявить единицы и отсутствие значения.
- Отделить ошибку от успешного пустого результата.

## Публичный контракт

ResultV1 всегда содержит version/status/value/reason: unknown имеет value=null и строковую reason; known имеет исходное значение и reason=null.

## Зависимости

- Core не импортирует MCP SDK ради DTO.

## Состояние и время жизни

Объект результата неизменяемый; cursor связывается с source/config identity.

## Ошибки

- Несовместимая версия отклоняется явно.

## Пример

```python
def amount_result(value):
    """Возвращает копейки либо unknown с явной причиной отсутствия."""
    if value is None:
        return {"version": 1, "status": "unknown", "value": None, "reason": "source-not-provided"}
    return {"version": 1, "status": "known", "value": value, "reason": None}
```

Неизвестное значение отличается от фактического нуля; обе ветви содержат reason с договорённой nullability.

## Контрпример

```python
def amount_result(value):
    return {"value": value or 0}
```

Falsy fallback стирает различие неизвестного и измеренного результата.

## Как внедрять

- Опишите текущий контракт до изменения.
- Проверьте старые входы/выходы на новом ядре.

## Ограничения

- Schema hash не доказывает поведенческую совместимость.

## Что проверять

- Проверить null, ноль, ошибку и неподдержанную версию.
- Проверить единицы и ограничения scope.

## Альтернативы

- Локальный тип без version field, если границы версий нет.

## Как писать код

- Описание метода объясняет вход, результат и существенные ошибки; комментарий ветви объясняет причину.
- Используйте ясные локальные этапы и ранние выходы; новый класс или интерфейс нужен только для самостоятельной ответственности.
