# Подготовка и смена поколения ядра

Новые вызовы переходят на готовое поколение; принятые остаются у старого до завершения или явной отмены.

## Задача

Замена backend во время вызова смешивает состояние, результаты и маршруты отмены.

## Когда применять

- Проверена возможность одновременного существования N и N+1.
- Есть контракт хранения, handles и ограниченный drain.

## Когда не применять

- Обратная совместимость storage не установлена.
- Старое поколение нельзя удержать для активных владельцев.

## Граница класса или папки

Класс lifecycle coordinator владеет prepare/switch/drain; dispatch lease отделён от бизнес-логики.

## Ответственность

- Проверить candidate до переключения.
- Закрепить generation за каждым принятым вызовом.

## Публичный контракт

Switch атомарен для новых вызовов; cleanup ждёт нулевого числа владельцев и compatibility gate.

## Зависимости

- Coordinator знает readiness/dispatch port, но не вычислительный алгоритм.

## Состояние и время жизни

Lease, background jobs и subscriptions удерживают нужное поколение до явного освобождения.

## Ошибки

- Startup failure оставляет текущий маршрут; irreversible migration запрещает обратный переход.

## Пример

```python
def choose_generation(candidate_ready, compatible, current, candidate):
    """Выбирает маршрут только для новых вызовов; leases отдельно."""
    if candidate_ready and compatible:
        return candidate
    return current
```

Упрощённый guard не выдаёт candidate до readiness; полный lifecycle требует leases/drain и отдельной квалификации.

## Контрпример

```python
def choose_generation(candidate_ready, compatible, current, candidate):
    return candidate
```

Новая версия выбирается даже при неготовности и несовместимости.

## Как внедрять

- Определите in-flight и storage owner.
- Проверьте candidate и только затем разрешите switch.

## Ограничения

- Логический rollback маршрута не равен физическому rollback executable.
- Frozen-reader packaging имеет отдельные ограничения; один rename их не решает.

## Что проверять

- Длительный вызов завершается на N, новый идёт на N+1.
- Отмена и timeout не приводят к повторной мутации.

## Альтернативы

- Отложить обновление до окончания операций.

## Как писать код

- Описание метода объясняет вход, результат и существенные ошибки; комментарий ветви объясняет причину.
- Используйте ясные локальные этапы и ранние выходы; новый класс или интерфейс нужен только для самостоятельной ответственности.
