# Кеш с идентичностью источника

Повторное использование связано с source hash, настройками и версией вычисления; лимит и invalidation явные.

ID: `source-bound-cache` · версия: `1.0.0` · статус карточки: **draft**.

Content hash: `ecfe877c3d6206aa135e68edd122d65c8aad99d5dbefec205b4dca48ecbdfa7d`.

Catalog version: `3b1765c0fa5449368237cddb8631362e34807809260037307e3e8e95780f3fa5`.

Квалификация применения в проекте: **not-assessed**. Чтение карточки не подтверждает внедрение.

## Задача

Кеш по имени файла возвращает данные другой редакции или других параметров.

## Когда применять

- Одно вычисление повторяется в совместимом контексте.
- Есть измеренная повторная стоимость.

## Когда не применять

- Ключ не содержит все существенные входы.
- Кеш быстрее только по предположению и дублирует существующий механизм.

## Граница класса или папки

Класс контекста или папка reuse contract; алгоритм не управляет глобальным кешем.

## Ответственность

- Проверить identity до reuse.
- Ограничить объём и срок, запретить публикацию после expiry.

## Публичный контракт

key=(source_hash,settings_hash,analyzer_version); miss и отказ reuse различимы.

## Зависимости

- Provider отдаёт immutable result.
- Owner lifetime управляет eviction.

## Состояние и время жизни

RAM-кеш принадлежит явно выбранному task/service; disk snapshot хранится отдельно.

## Ошибки

- Истёкший контекст и смена источника не маскируются текущим результатом.

## Пример

```python
def cache_key(source_hash, settings_hash, analyzer_version):
    """Связывает reuse со всеми значимыми версиями входа."""
    return source_hash, settings_hash, analyzer_version
```

Идентичность включает версии источника и вычисления, а не только путь.

## Контрпример

```python
def cache_key(filename, settings_hash, analyzer_version):
    return filename
```

Одинаковый путь не доказывает одинаковые данные и параметры.

## Как внедрять

- Сначала измерьте повторные вычисления.
- Проверьте существующий cache/context перед добавлением нового.

## Ограничения

- TTL сам по себе не гарантирует актуальность источника.

## Что проверять

- Сравнить cold/reused результат.
- Изменить source/settings/provider и проверить invalidation.

## Альтернативы

- Не кешировать дешёвую операцию.

## Как писать код

- Описание метода объясняет вход, результат и существенные ошибки; комментарий ветви объясняет причину.
- Используйте ясные локальные этапы и ранние выходы; новый класс или интерфейс нужен только для самостоятельной ответственности.
