# Данные и обновления

Исполняемые файлы отделены от базы знаний:

- macOS: `~/Library/Application Support/Code Atlas`.
- Windows: `%LOCALAPPDATA%/Code Atlas`.
- Linux: `$XDG_DATA_HOME/code-atlas`, обычно `~/.local/share/code-atlas`.

Здесь сохраняются реестр проектов, снимки Graphify, производные группировки,
представления с заметками и настройки MCP документации. Клоны Git лежат рядом.
Исходники локальных проектов остаются в исходных каталогах; база их не заменяет.

## Перенос прежней установки

Остановите старый сервер. Запустите новый executable с
`--migrate-from /absolute/path/to/old/.atlas` (при необходимости --data-dir).
Перенос копирует данные, исправляет внутренние ссылки снимков и сохраняет старый
каталог. Непустое назначение не перезаписывается. Каталог с неподдерживаемой
версией схемы не открывается старым приложением.

## Обновление

1. Дождитесь завершения заданий и остановите приложение.
2. Для текущего checkout выполните `sh packaging/update-local.sh --build`
   (macOS/Linux) или `.\packaging\update-local.ps1 -Build` (Windows).
   Для готового пакета из `dist` опустите параметр сборки.
3. Скрипт проверяет архитектуру, готовый runtime и схему данных, затем вызывает
   installer: он заменяет только приложение, сохраняя предыдущую установку
   для отката. Совместимое обновление не копирует и не архивирует данные.
4. Запустите приложение и проверьте список проектов и сохранённые представления.

Скрипт открывает приложение после установки; `--no-start` / `-NoStart` отменяет
этот шаг. Пути, выбор нативного Python, ARM64 и проверочный режим описаны в
[инструкции обновления](../../packaging/UPDATING.md).
Для отдельной ручной копии используйте `--backup-data`: ZIP создаётся в соседнем
каталоге backups. Резервное копирование и перенос схемы — отдельные операции.

Автоматической загрузки обновлений из интернета нет. Пакет обновления можно
перенести офлайн. Откат к старой версии допустим только при совместимой схеме;
иначе восстановите соответствующую резервную копию в отдельный каталог.

## Снимки, кэш и место на диске

Новые снимки хранятся как manifest со ссылками на сжатые объекты. Неизменившиеся объекты могут использоваться несколькими ревизиями; центральный reader восстанавливает исходные ID, значения и связи. Прежние JSON-снимки продолжают читаться. Исходный Graphify результат сохраняется отдельно, а совместимая MCP-проекция создаётся по запросу.

Сжатие и повторное использование уменьшают занимаемое место. Полная загрузка требует распаковки и не обещает экономии RAM или ускорения. Общий индекс разрешения связей Graphify по-прежнему охватывает проект. Эти изменения не разрешают автоматическое удаление старых снимков, экспортов или истории.

Временный analysis context агента хранит синтаксис в RAM и истекает после 20 минут без полезных обращений. Это отдельный жизненный цикл: истечение контекста не удаляет снимок. Локальный кэш извлечения Graphify также отделён от истории; повторное использование зависит от языка, исходников и конфигурации.

## Очистить снимки или удалить карты

Если папка опубликованного снимка удалена вручную, открытие текущей карты или
поиск без закреплённой ревизии запускает одну попытку восстановления из доступных
исходников. После ошибки повторную сборку запускают явно. После намеренной
очистки автоматической пересборки нет. Оставшуюся регистрацию можно убрать
отдельной кнопкой **«Удалить запись из списка»** с подтверждением; это действие
не удаляет исходники, файлы снимков или сохранённые виды и не освобождает их объём.

В **Техническая страница → Хранилище карт** выберите карты кода или данных,
выберите одно из двух действий и проверьте список, даты, объём и последствия:

- **«Очистить снимки — оставить запись»** удаляет текущие и предыдущие снимки,
  сохраняя карту в списке как **«Не построена»** для явного построения заново.
- **«Удалить выбранные карты»** удаляет снимки вместе с регистрациями.
  После завершения выбранные карты исчезают из списка.

Исходники, сохранённые авторские виды, карты документов и настройки остаются
в обоих случаях. Отдельная кнопка **«Удалить запись из списка»** сохраняет файлы
снимков и подходит для уборки регистрации без очистки её файлов.
Неизвестное содержимое блокирует удаление карты так же, как очистку снимков.

Неизвестная версия снимка не доказывает, что его алгоритм устарел. Изменение карты
после предварительного просмотра требует нового подтверждения. При разрыве
соединения сначала проверьте результат прежней операции; незавершённое удаление
может оставлять данные на диске. При запуске сервер может продолжить очистку уже
подтверждённых временно перемещённых данных, включая частично удалённые. Это не
разрешает удалять новые снимки. История операции доступна в разделе незавершённых
очисток; просмотр состояния ничего не запускает. Объём файлов логический и не
гарантирует столько же свободных блоков диска. После успешного удаления отмены
нет. Исторические виды остаются читаемыми, но их ссылки на удалённый снимок могут
перестать работать. Подробнее об устройстве хранения: [Чанки и хранение](Chunked-Analysis.md).

Wiki модов читаются из установленного пакета без активации. Markdown входит в общий fingerprint: даже изменение текста требует обновить каталог и явно подтвердить новую исполняемую ревизию, если мод содержит код.
