# Временные карты checkout для агентов

Сверено по исходникам: 2026-10-30.

Для рабочей задачи агент создаёт собственную карту через `ensure_checkout_map(checkout, ownerKey)`. Исходная папка читается на месте; её файлы не копируются и не удаляются. Каждая пара «абсолютный checkout + ключ задачи» получает отдельную папку Atlas и отдельный ProjectStore. Постоянные регистрации и карты других задач не перестраиваются.

## Срок жизни

Карта действует один час после последнего успешного полезного обращения: поиска, описания узла, оценки здоровья, прогноза или сравнения. Ошибка, статус сборки, список и повторный ensure не продлевают срок. Агент сохраняет sessionId и использует его явно во всех checkout-tools. Истёкшая сессия не возрождается; новая задача получает новую карту.

Закрытие Atlas сохраняет срок истечения. Пока приложение работает, очистка выполняется фоновым обслуживанием; после остановки приложения истёкшие папки очищаются при следующем запуске. Это срок допуска к карте, а не обещание удаления байтов ровно в указанную секунду.

## Посмотреть и удалить

Откройте **Техническая страница → Временные карты checkout**. Строка показывает отметку «Временная», исходный checkout, путь временной папки, снимок, срок и состояние. Кнопка «Удалить» действует только на выбранную карту. Активное чтение или построение сначала завершается; ожидание удаления и ошибка очистки остаются видны. Для повторного удаления после ошибки предусмотрен явный повтор.

Агент может завершить работу через `finish_checkout_map(sessionId)`. Не удаляйте папки вручную во время работы сервера. На неизвестные каталоги и символические ссылки очистка не распространяется; небезопасное хранилище временных карт становится недоступным без остановки постоянных карт.

## Рабочий порядок

1. Ensure с постоянным ключом текущей задачи; дождаться snapshot и завершения activeJob через get_checkout_map.
2. Поиск `search_checkout_nodes`, затем описание по точным snapshotId/raw nodeId. Partial и неизвестные зависимости сохраняются в выводах.
3. Перед правками — working-tree baseline через get_checkout_code_health, затем прогноз и после правок измерение/сравнение.
4. После законченной серии правок один раз явно вызвать rebuild_checkout_map и повторить поиск в новом снимке. Чтение само карту не перестраивает.
5. При завершении освободить свою сессию или оставить её на обычное истечение срока; не посылать keepalive ради удержания папки.

При отсутствии новых tools доступен тот же явный HTTP scope `/api/checkout-sessions`. Все POST требуют JSON, включая `{}` для rebuild. Привязанный к постоянному проекту MCP не переключается скрытно на временную карту: нужен общий host connection. Установка skill направляет поведение агента; она не создаёт безусловный IDE hook.

## Ограничения

По умолчанию допускаются четыре одновременные временные карты, жёсткий предел — восемь. Карты не вытесняют соседей молча. Это ограничение количества, а не дисковая квота. Разные карты не защищают от одновременной правки одних исходных файлов: при изменении во время извлечения сборка может отклонить публикацию и потребовать согласованного повторного построения.

Новая функциональность проверена в исходной сборке с отдельным HTTP/MCP и браузерным стендом. Это не подтверждение установки в уже работающий native Atlas. Сохранённые raw/source identity остаются исходными; отдельный sessionId определяет владельца временного хранилища.

## Обзор изменений агента

1. До правок дождитесь свежего снимка своей временной карты. Найдите одну функцию через `search_checkout_nodes` и передайте её raw ID, ID снимка и ID сессии в `begin_change_review`. Карта может включать уже существующие незакоммиченные правки. Сохраните возвращённый `reviewId`.
2. После правок вызовите `rebuild_checkout_map`, дождитесь нового снимка и передайте его вместе с `reviewId` в `finish_change_review`. Пока Atlas строит карту и фиксирует путь, дождитесь завершения редактирования. Если первая сессия истекла, создайте карту того же checkout с тем же `ownerKey`.
3. Передайте пользователю локальный URL из результата. В обзоре можно сопоставить две версии пути и открыть сохранённые координаты функций. `get_change_review` возвращает постраничный список функций. Обзор хранится в локальных данных Atlas отдельно от временных карт.

Сопоставление использует захваченную идентичность объявления и хеш его текста. Сдвиг строк сам по себе не считается изменением. При смене сигнатуры или файла функция может появиться отдельными строками добавления и удаления. Покрытие зависит от фактов, полученных при построении каждой карты. Atlas сверяет байты файлов из инвентаря в пределах бюджета и сообщает, если проверил только часть. Новые файлы вне снимка выявляет пересборка. Путь статический, а его исходные события сохраняются только при совпадении байтов со снимком. Нужна карта, построенная версией Atlas с поддержкой обзоров.

Клиент без MCP использует `POST /api/change-reviews` с `sessionId`, `snapshotId`, `nodeId` и необязательным `title`, затем `POST /api/change-reviews/{reviewId}/finish` с `sessionId` и новым `snapshotId`.
