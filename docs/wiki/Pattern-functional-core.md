# Чистое ядро и оболочка I/O

Вычисления получают значения и возвращают значения; оболочка владеет чтением, сохранением и внешними эффектами.

## Задача

Тест правила требует базы, часов или сети, потому что вычисление само получает окружение.

## Когда применять

- Чистая функция или алгоритм смешаны с I/O.
- Одинаковые правила нужны CLI, HTTP и MCP.

## Когда не применять

- Основной смысл операции — единственный простой внешний вызов.

## Граница класса или папки

Папка rules или чистые функции внутри feature module; оболочка отдельно вызывает порты.

## Ответственность

- Преобразовать входные значения.
- Оставить эффект во внешнем оркестраторе.

## Публичный контракт

total(amounts) -> сумма; входные данные не изменяются.

## Зависимости

- Ядро не импортирует HTTP, MCP SDK или драйвер базы.

## Состояние и время жизни

Вычислительное ядро не имеет скрытого состояния; оболочка явно управляет ресурсами.

## Ошибки

- Ошибка чтения принадлежит оболочке, ошибка входных значений — контракту ядра.

## Пример

```python
def total(amounts):
    """Возвращает сумму копеек, не изменяя коллекцию."""
    return sum(amounts)

def report(read_amounts, write_total):
    amounts = read_amounts()
    result = total(amounts)
    write_total(result)
```

Чистое правило проверяется на значениях, оболочка имеет явные операции I/O.

## Контрпример

```python
def total(db):
    amounts = db.query_all()
    result = sum(amounts)
    db.save_total(result)
    return result
```

Один метод скрывает загрузку и запись под названием вычисления.

## Как внедрять

- Вынесите уже загруженные значения в аргументы правила.
- Оставьте порядок I/O в короткой оболочке.

## Ограничения

- Не материализуйте огромный ленивый поток только ради разделения.

## Что проверять

- Повторные одинаковые входы дают одинаковый результат.
- Ошибка записи не меняет смысл рассчитанного результата.

## Альтернативы

- Обычный метод без новой абстракции для одной простой операции.

## Как писать код

- Описание метода объясняет вход, результат и существенные ошибки; комментарий ветви объясняет причину.
- Используйте ясные локальные этапы и ранние выходы; новый класс или интерфейс нужен только для самостоятельной ответственности.
