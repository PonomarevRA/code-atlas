# Архитектурные проверки

Первая версия проверяет **статические объявления в явно выбранной области**.
Результат не описывает фактические runtime-вызовы. Один движок используется
сервисом, HTTP/MCP и CLI; UI-проекция в анализ не поступает.

## Контракт v1

```json
{
  "version": "atlas-architecture-v1",
  "pythonRoot": ".",
  "layers": [
    {"id": "language", "paths": ["atlas/flow_languages/*.py"]},
    {"id": "http", "paths": ["atlas/server.py", "atlas/*_api.py"]}
  ],
  "rules": [
    {"id": "language-boundary", "kind": "forbidden", "layers": ["language"],
     "target": ["http"], "relations": ["python-import"]}
  ]
}
```

`exclude` (до32 записей) явно исключает относительные файлы/каталоги из
области и inventory: например `["outputs", "sites"]`. Это буквальные POSIX
пути без glob/выхода за корень. Исключения входят в отпечаток правил: изменение
области несовместимо с прежним baseline. Лимит inventory остаётся строгим.

Конфигурация строгая: неизвестные поля, версии, отношения и ссылки на слои
отклоняются. До 32 слоёв и 100 правил. `paths` — относительные POSIX fnmatch
шаблоны (`*` может включать `/`). Вместо paths можно указать `projects` — точные
ID из снимка. Слои не должны пересекаться. Пустые/неоднозначные области дают
`unknown`. Проектная область опирается на опубликованный inventory и пока
не доказывает полноту: положительное доказательство возможно, `passed` — нет.

`forbidden` запрещает прямые направленные рёбра из `layers` в `target`.
`cycles` проверяет индуцированный файловый граф объединения `layers`, без
`target`; возвращает один замкнутый путь на циклическую SCC. Это не список
всех простых циклов и не циклы runtime/между агрегированными слоями.

Отношения:

- `python-import`: AST `import`/`from`, включая вложенные объявления и пакеты
  предков. Требует явный `pythonRoot` (`.` или, например, `src`). Имена модулей
  выводятся из файлов относительно этого каталога. Коллизии имён дают unknown.
  Исполнение, sys.path, динамические импорты, подмена exports и runtime binding
  не моделируются; `passed` относится только к этим лексическим объявлениям.
- `project-reference`: буквальные XML ProjectReference. Условия MSBuild не
  исполняются: факт означает присутствие декларации. Вычисляемая/внешняя ссылка
  остаётся unknown. Подходящие paths выбирают именно манифесты .NET.
- `code-dependency`: выбранные raw calls/references/imports/inherits/implements/
  dispatches_to с resolved/EXTRACTED confidence и совпадающими byte hashes
  обоих исходников. Топология снимка не считается полной: отсутствие нарушения
  даёт unknown. Legacy/inferred/ownership edges не являются доказательством.

## Достоверность и ограничения

Вход фиксирует snapshotId, analyzerVersion, правила, sourceFingerprint и SHA256
байтов. Файлы читаются безопасным просмотрщиком без исполнения; после захвата
хеши и inventory проверяются повторно. Изменившиеся факты отбрасываются.
Это оптимистическое наблюдение рабочей копии, а не атомарная filesystem snapshot.

`violated` означает подтверждённый путь даже при неполноте других фактов.
`passed` возможен только при полной области соответствующего типа зависимости.
`unknown` содержит причины: unsupported/parse/stale/ownership/inventory/budgets.
Есть лимиты 20 000 путей, 16 MiB текста, 1 MiB на файл, 100 000 связей и 1000
сохраняемых нарушений. Лимиты не преобразуют unknown в passed; усечение явное.
Исключены .git, .venv/venv, node_modules, __pycache__, build/dist и каталоги skills.
Symlink-каталоги не обходятся; их наличие делает inventory неполным. Исходный
граф и файлы не меняются. Сдвиг строк меняет provenance, но не ID того же ребра.

## HTTP, MCP и интерфейс

Страница `/architecture.html?repo=<projectId>` доступна из меню «Страницы Atlas».
Выберите проект, задайте JSON и явно запустите проверку. Статусы и причины не
зависят от цвета. Нарушение открывает карту направленных файловых связей;
кнопка исходника выделяет связь и открывает проверенный фрагмент. Escape
закрывает диалог и возвращает фокус. Путь из нескольких страниц обозначается
как частичный; полный цикл подтверждается сохранённым результатом движка.
ID цикла фиксирует все направленные связи его SCC, а показанный путь — один
представитель. Изменение циклической топологии требует нового рассмотрения baseline.
Изменение проекта сбрасывает результат и отменяет доставку старого ответа.
После изменения правил показанный запуск помечается как предыдущий.

HTTP использует `/api/projects/{projectId}/architecture-checks`:

- `POST` `{snapshotId,rules}` запускает анализ и выдаёт первую страницу правил.
- `GET /{runId}?collection=rules|findings&offset=0&limit=20` читает сохранённый run.
- `GET /{runId}/findings/{findingId}?offset=0&limit=20` читает путь доказательства.
- `POST /{runId}/findings/{findingId}/source` `{edgeIndex}` открывает фрагмент
  источника с SHA256; произвольное имя файла не принимается.

`nextOffset` учитывает действительно доставленные элементы. Общий бюджет
HTTP/MCP страницы — 64 000 UTF-8 JSON bytes. `deliveryTruncated` означает
сокращение страницы, `findingsTruncated` — неполноту сохранённого списка нарушений.
MCP: `run_architecture_checks`, `read_architecture_checks`,
`read_architecture_evidence`, `read_architecture_source`. Все проксируют тот же
сервис, сохраняя привязку MCP к проекту; своего filesystem scanner у MCP нет.

Результаты только в RAM: срок до часа, максимум 16 runs/32 MiB суммарно,
8 MiB на run. Один анализ одновременно. Eviction/restart/TTL дают404 и требуют
нового запуска; чтение не продлевает TTL. Смена карты или байтов источника
перед открытием даёт409. Незавершённые/устаревшие ответы не подменяют новый UI.
Карта результатов — сохранённое наблюдение, а исходник проверяется заново.

## Baseline и headless CLI

CLI использует тот же capture/evaluate, но читает текущую папку без ProjectStore,
сервера и UI. `snapshotId=source-only`; проектные selectors и raw code-dependency
без снимка остаются unknown. Для source-backed CI выбирайте файловые области
и python-import или буквальные project-reference манифестов.

```sh
python -m atlas.architecture_cli check --root . --rules architecture-rules.json
python -m atlas.architecture_cli check --root . --rules architecture-rules.json --format json
```

В standalone-сборке тот же CLI запускается без внешнего Python:
`CodeAtlas -m atlas.architecture_cli check --root <папка> --rules <rules.json>`.
На macOS executable находится внутри `Code Atlas.app/Contents/MacOS/CodeAtlas`.
Разрешён только фиксированный внутренний модуль, произвольный `-m` запрещён.

В репозитории четыре проверенных правила: языковые провайдеры, Graphify adapter
и общий движок не импортируют HTTP/MCP transport; внутри общего движка нет
файловых циклов. Это прямые лексические границы, без утверждения об отсутствии
транзитивной или динамической зависимости. Команда включена в существующие
GitHub/GitLab native pipelines после установки зависимостей. Удалённый CI при
этой реализации не запускался; локально выполнена та же команда.

Baseline создаётся **явно** только из полного неусечённого результата:

```sh
python -m atlas.architecture_cli baseline --root . --rules architecture-rules.json --write architecture-baseline.json
python -m atlas.architecture_cli check --root . --rules architecture-rules.json --baseline architecture-baseline.json
```

Существующий файл не перезаписывается без `--replace`. Обновление baseline —
отдельное принятие исходного списка, а не часть обычной проверки CI. Baseline
фиксирует версии, смысл правил/областей и исходный fingerprint. Строки и байты
доказательства могут измениться без смены ID того же правила/ребра/пути.
Изменение правил или анализатора несовместимо: требуется явный новый baseline.

Сравнение выдаёт `new`, `existing`, `resolved`, `unconfirmed`. Отсутствие старого
ID считается устранением только при полной текущей области и неусечённом
списке. Иначе это unconfirmed. Для циклов ID фиксирует всю топологию SCC: любое
изменение внутренних направленных связей требует нового рассмотрения. Старый
цикл считается resolved только когда при полном анализе правило больше не
содержит циклов; пока остаётся любая циклическая компонента — unconfirmed.
Статусы самих правил сохраняются: принятый
existing всё равно violated; advisory unknown всё равно unknown.

Exit codes:

| Код | Условие |
| --- | --- |
| 0 | Нет новых нарушений, требуемое покрытие полное; либо явно выбран `--unknown warn` |
| 1 | Есть нарушение без baseline или новый ID относительно baseline |
| 2 | Неполнота/unknown/усечение без новых подтверждённых нарушений при default `--unknown fail` |
| 3 | Неверный JSON/контракт, несовместимый baseline, ошибка чтения или записи |

`--unknown warn` — явная advisory-политика, а не превращение unknown в passed.
Baseline не создаётся из unknown даже с такой политикой. CLI не исполняет
анализируемый код, MSBuild, package manager или сетевые запросы.
