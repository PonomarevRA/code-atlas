# HTML-мод и автоматический выбор анализаторов

`mods/language-html/mod.json` выбирает встроенный `html-structure-v1`. Мод
декларативный, без JS/Python entrypoints. HTML5-разбор и CSS-селекторы используют
локальные pure-Python html5lib/cssselect2, без нативного C-парсера. Он применяется
при обновлении карты, если есть `.html` или `.htm`, и не запускает код сайта.

## Факты HTML

Снимок получает узлы страниц/фрагментов и всех элементов исправленного HTML5-дерева.
Неявные html/head/body/tbody и восстановленные formatting nodes явно помечены generated;
собственного исходного диапазона у них нет. У каждого элемента есть namespace,
CSS-селектор и переходы к родителю/детям. Связи contains отражают структуру;
references связывают известные локальные HTML-файлы. CSS/assets/form action
сохраняются как буквальные ссылки с разрешённым файлом или статусом unresolved.
Пути с обходом, URL и динамические выражения не загружаются и не исполняются.

`htmlFacts` доступны в полном узле, describe_node и компактном analysisFacts.html
поиска/соседства. Инспектор карты показывает ограничения, рекомендации и места
дубля с переходом к точному ID блока. Строки и SHA256 относятся к захвату исходника,
не к текущему DOM. Raw-файл Graphify, его ID и исходные рёбра не переписываются.

Дубли — точное совпадение исходных поддеревьев от четырёх элементов и 100 символов.
Значимые атрибуты, тексты, обработчики и пробелы не удаляются. Вложенные повторы
одного большого блока не дают повторных советов. Сначала предлагаются существующие
компоненты/layout/partials; при отсутствии сборки — статическая генерация JS
framework или шаблонизатором. Runtime JavaScript не требуется. Штраф H/O/T и
автоматическое переписывание отсутствуют.

Поддерживается HTML, не JSX/TSX или произвольные языки шаблонов. Неподдержанные
шаблонные конструкции и parse errors дают partial;
для такого файла дубли не доказываются. Optional end tags, таблицы и некорректная
вложенность обрабатываются html5lib. Отдельный template.content не поддерживается
версией 1.1: CSS-поиск такого файла отклоняется явно.
Сравнение похожих, но различных фрагментов остаётся следующим этапом плана.

## Исходники и результат сборки

Если известны каталоги, укажите в корне проекта `atlas-html.json`:

```json
{"sourceRoots":["src"],"generatedRoots":["public-output"]}
```

Только относительные пути внутри проекта; JSON не исполняется. Без manifest
область исходников — `.`. Файлы под dist/build/out/_site остаются unknown-output
и не участвуют в рекомендациях о дублировании, пока источник не указан явно.
Это не утверждение, что любой каталог с таким именем обязательно сгенерирован.
Известные generated roots исключаются полностью. Ошибка manifest видна в
metadata.htmlAnalysis и не приводит к угадыванию области исходников.

Общий file inventory использует ограниченный read-only `git ls-files` с
выключенными fsmonitor/hooks, учитывая Git ignore. Для папки без Git есть bounded
обход без ссылок/служебных и скрытых каталогов; его ограничения и отсутствие
применения gitignore явно записываются в metadata анализа.

Бюджеты: inventory 20 000 файлов/2 MiB путей; HTML 200 файлов, 1 MiB на файл,
16 MiB чтения всего, 20 000 элементов суммарно и глубина 128; до 5000 derived
узлов, 100 групп дублей, 40 захваченных мест на группу, 40 ссылок на страницу.
Хеширование кандидатов ограничено 16 MiB. Достижение бюджета помечается truncated;
отсутствие совпадений в неполном анализе не доказывает отсутствие дублей.

## Автоматика модов

По умолчанию bundled analysis-only моды находятся в режиме «Авто по файлам».
Языковые моды используют свои extensions; build-моды — объявленные markers;
библиотечные моды — типы файлов соответствующего языка. Последнее означает
применимость анализатора: наличие Java само по себе не доказывает JUnit.
Факты появляются лишь при совпадении правил конкретной библиотеки.

Пользовательский analysis-only мод может объявить autoActivate с точными
extensions/manifestNames. Пакет лежит в каталоге модов Atlas, не анализируемом
репозитории. Авто недопустимо для frontend scripts, grouping, workflows и
оформления. Зависимости должны иметь собственное основание для выбора; ручное
выключение зависимости не обходится.

На `/mods.html` доступны «Авто по файлам», «Включить вручную», «Выключить»,
глобальный переключатель автоанализа и «Отключить все». Ручной off и изменённая
закреплённая вручную версия приоритетнее auto. Отсутствующие настройки означают
default auto; повреждённые настройки блокируют auto, а не забывают off.
Автоматический выбор не записывает глобальное включение и не меняет оформление.

Снимок хранит версии, fingerprints, режим выбора и примеры совпавших файлов.
Обычные запросы UI/MCP читают эти факты, без повторного сканирования каталога.
Проверка актуальности настроек тоже не читает репозиторий. После смены файлов,
мода или политики требуется обновить карту; старые снимки неизменяемы.


## CSS-поиск по дереву снимка

В инспекторе HTML-узла есть CSS-селектор и поле «CSS-поиск в HTML-файле».
Примеры: `nav > a[href]`, `table > tbody > tr`, `.card:nth-child(2)`,
`section:has(> h2)`, `svg|circle`. Результат выбирает точную карточку.
Ищется весь файл, даже если выбран вложенный элемент; не текущая видимая область.

Агент использует `query_html(snapshotId, nodeId, selector, projectId, offset, limit)`.
Сначала найдите HTML-узел через search_nodes, затем закрепите snapshotId.
HTTP: POST `/api/projects/{projectId}/html-query` с теми же полями без projectId.
После обновления приложения MCP-клиенту нужно перечитать каталог инструментов.
Старым картам без дерева требуется обновление; CSS-запрос не перестраивает их.

`:hover`, `:focus`, `:visited` и псевдоэлементы требуют browser state или не являются
элементами, поэтому возвращают объяснимую ошибку. Страница ответа ограничена 50
элементами; nextOffset продолжает тот же selector/snapshot. У autogenerated nodes
line/start/end могут быть null — это не отсутствие HTML5-узла.
