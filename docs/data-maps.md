# Карты данных

Карты CSV, JSON/JSONL/NDJSON и Gherkin `.feature` находятся в отдельном слое.
Открытие и индексирование проекта не строят их. Поиск подходящих файлов читает
только имена и stat. Кнопка «Посмотреть карту данных» появляется в обычном
проекте при наличии таких файлов; создание требует выбора файлов и нажатия
«Построить выбранные файлы». Также можно указать самостоятельный каталог.

## Снимки и актуальность

Каждый ответ анализа содержит `mapId`, `snapshotId`, `builtAt`,
`lastVerifiedAt`, `freshness.status`, `freshness.checkedAt`,
`freshness.changedFiles` и `freshness.changedFileCount`. Даты — ISO 8601 UTC.
`builtAt` — время публикации анализируемого снимка, `lastVerifiedAt` — время
последней проверки содержимого источников. При чтении свежесть определяется по
размеру, mtime, ctime и inode; поле `verification` указывает способ проверки.
Это не обещание неизменности источника после ответа.

Изменение или удаление источника даёт `freshness.status="stale"`, **не ошибку**.
Чтение сохраняет прежние данные и дату: агент сам решает, требуется ли обновление.
Если требуется анализ текущих файлов, он явно вызывает `ensure_data_map`,
который проверяет SHA-256 и запрашивает импорт только при изменении (либо `force`).
Нужно дождаться `get_data_job.status="completed"` и получить новый `snapshotId`.
Ни watcher, ни чтение, ни старт сервера не запускают построение.

Ошибка `SNAPSHOT_MISMATCH` означает смену опубликованной ревизии, а не устаревание
исходников. После неё получают новый обзор и заново проверяют ID. Не подставляют
новый snapshotId в старые результаты молча. Неудачный или отменённый импорт
сохраняет предыдущий снимок. Источники копируются и проверяются до публикации;
координаты и хеши относятся к захваченному файлу.

## Работа через MCP

| Инструмент | Назначение |
| --- | --- |
| `discover_data_files` | Имена и размеры подходящих файлов; ничего не строит |
| `list_data_maps` | Уже существующие карты, даты и свежесть |
| `create_data_map` | Явный набор файлов, настройки CSV и индексируемых полей |
| `ensure_data_map` | Явная проверка SHA-256 / актуализация |
| `get_data_job`, `cancel_data_job` | Прогресс и отмена запрошенного импорта |
| `get_data_overview`, `get_data_schema` | Даты, дерево файлов/коллекций/полей/сценариев |
| `find_data_relations` | Заданные правила и кандидаты совпадений с охватом |
| `query_data_records`, `get_data_record` | Страницы точных записей и координаты источника |
| `search_data_scenarios`, `get_data_scenario` | Пояснения, фон, шаги и выбранный Examples |
| `trace_data_links` | Локальный подграф записей, курсоры продолжения |
| `create_data_view` | Исторический сохранённый вид отдельного слоя |

`--project-id` ограничивает инструменты картами, созданными для выбранного
проекта. `--data-map-id` фиксирует одну уже существующую карту, без обнаружения
и создания других. Это ограничение MCP-прокси; локальный HTTP API не является
многопользовательским сервером авторизации. Поставляемый skill находится в
`skills/code-atlas/SKILL.md`; конфигурация и ZIP доступны в настройках агентов.

Все чтения закрепляются за snapshotId. Пагинация возвращает `nextCursor`;
параметры запроса при продолжении сохраняют. У графа `continuations` содержат
recordId/cursor для дальнейшего чтения fan-out; прежние maxDepth/maxNodes и
relationIds сохраняют. Передаются только ограниченные результаты, без raw SQL.
`query_data_records.filters` принимает `eq`, `ne`, `isNull`, `missing` для
индексируемых полей. Отсутствующее поле отличается от явно заданного null.

CSV сохраняется строками, включая ведущие нули. Заголовки обязательны, пустые
и повторяющиеся заголовки отклоняются. UTF-8 / Windows-1251 и разделитель
задаются при построении. JSON сохраняет целые числа точно; Decimal в ответе
представлен точной строкой с `provenance.valueTypes[path]="number"`.
Реальные ссылки на вынесенные массивы дополнительно перечислены в
`provenance.collectionReferences`; похожий пользовательский JSON-ключ не
считается ссылкой. Пути полей — JSON Pointer с экранированием `/` и `~`. Массивы вынесены в
отдельные коллекции, записи связаны с родителями. JSONL координата `/N/...`
обозначает индекс JSON-документа и путь внутри него, а не строку исходника.

Автоматические связи ищутся между подходящими именами индексируемых полей;
совпадение значения не доказывает бизнес-связь. `candidate` / `inferred`
отделены от пользовательского правила `declared` / `user-declared`.
Статистика каждого проверенного правила охватывает полный снимок и показывает
совпадения, отсутствующие/null ключи и дубликаты; перебор кандидатов ограничен.
Для CSV-строки и JSON-числа правило может явно задавать `compareAs="string"`:
это не превращает `001` в `1`. Правило задаётся по точным collectionId или
sourceFile/targetFile, если поле однозначно выбирает коллекцию файла.

Gherkin разбирается официальным AST-парсером Cucumber. Сохраняются описания,
комментарии с областью, Feature/Rule/Background, теги, сценарии, Examples,
Doc Strings и Data Tables. Выбранный пример подставляется в тексты шагов и
Doc Strings; Data Tables доступны отдельными коллекциями с исходными шаблонами.
Сценарии и Then остаются описанием ожиданий, `runtimeStatus="unknown"`:
импорт данных не запускает тесты и не подтверждает выполнение.

## Хранилище и ограничения

`/technical.html` показывает каталог хранения, даты карт кода и данных,
статус и занимаемые байты. Кнопка открывает управляемый каталог в файловом
менеджере. Размер данных включает SQLite, копии источников, предыдущие снимки
и staging. Свежесть исходников кодовых карт здесь явно помечена «не проверена».
Данные хранятся в `<data-dir>/data-maps/<mapId>/<snapshotId>/`; кодовые карты
и их публикация используют собственный каталог. Общих узлов и автоматических
связей между этими слоями нет.

Лимиты первой реализации: до 1000 выбранных файлов и 1 000 000 000 байт суммарно,
1 MiB на запись/JSON-токен, глубина JSON до 64, один `.feature` до 8 MiB,
2000 коллекций, 5000 полей, 20000 Gherkin-узлов на карту. Индексируется до 64
полей (можно выбрать `indexFields`), проверяется до 500 кандидатов; SQLite
ограничен 6 ГБ. Крупные наборы схемы разделяют на самостоятельные карты.
Страница — до 50 элементов и 64000 байт, локальный граф — до 120 узлов и
300 рёбер, SQL-бюджет — 5 секунд. Усечения явно отмечены; крупную запись
читают по отдельным `fields` через MCP. Обновления исполняются одним worker,
чтобы параллельные запросы не умножали потребление памяти.

Экспорт SVG сохраняет качество текущей видимой структуры, Graphify JSON
экспортирует компактные `nodes/links` без миллионов строк. Тесты:
`tests/test_data_maps.py`, `tests/test_data_api.py`, `tests/test_data_mcp.py`,
`tests/test_data_scene.mjs`. Воспроизводимый синтетический замер:
`.venv/bin/python scripts/benchmark-data-maps.py --bytes 1000000000`.

## Выполненные проверки (2026-10-10)

На локальном macOS / Python 3.13, с резервным Python-backend ijson:
999 991 588 байт CSV+JSON, 121 849 записей — 54,52 с, пиковый RSS 104,8 MiB;
страница из 20 выбранных записей — 3,8 мс. Это синтетический набор с двумя
файлами, текстовыми полями по 8 KiB и индексом `/id`; время для других схем,
числа индексируемых полей и Gherkin не выводится из этого замера.
Отдельный регрессионный тест проверяет предел памяти Python-backend.

Самопроверка code-quality-gate: обязанности разделены между захватом, парсерами,
индексом, запросами, публикацией, HTTP/MCP и интерфейсом. Обнаруженное удержание
буферов резервного JSON-парсера исправлено и повторно измерено. Проверки охватывают
точность чисел, нули CSV, null/missing, вложенные массивы, Gherkin/Examples, stale
без пересборки, атомарное сохранение прошлого снимка, область курсоров, byte/node
лимиты, реальный stdio MCP и отрисовку в браузере. Нативная сборка приложения и
установка в `/Applications` в этот запрос не входят и не проверены.


## Выбор ключа и изоляция пути

Над картой данных можно выбрать индексированное поле. Список сортируется по
`score = repeatOccurrences + matchedRecords`, затем по максимальной частоте
значения. `repeatOccurrences` — число повторений сверх первого для каждого
typed-значения, отличного от null, внутри коллекции. `matchedRecords` — максимальное
число совпавших строк по одному найденному или заданному правилу между
коллекциями, с учётом обоих направлений. Отсутствующие поля и `null` рейтинг
не повышают. Рейтинг отражает совпадения данных, а не важность поля для бизнеса.

Выбранный ключ занимает первую колонку, значения по убыванию частоты — вторую,
строки — третью, последующие связи — следующие колонки. Нажатие на значение
раскрывает соответствующие строки с координатами источника. «Изолировать путь»
убирает другие значения; «Показать остальные значения» возвращает их. Выбор
«Структура файлов» возвращает первоначальное дерево. `null` показан отдельной
группой и отличается от отсутствующего поля. Типы и ведущие нули сохраняются.

MCP предоставляет `rank_data_keys`, `get_data_key_values`, `get_data_key_path`.
`keyId` берётся из рейтинга, `valueRecordId` — из страницы значений; агенту
не требуется передавать само потенциально крупное значение. Курсоры закреплены
за картой, снимком, ключом, значением и параметрами запроса. `nextCursor` пути
продолжает строки группы в порядке исходных записей, до 16 корней на страницу.
Граф ограничен `maxNodes` (до 120), `maxDepth` (до 3), 200 связями и 64000 байт.
Для дополнительного раскрытия конкретной строки используется `trace_data_links`.
`truncated` сообщает ограничения. SVG экспортирует текущий путь, включая изоляцию.

Все три операции читают опубликованный снимок и возвращают `builtAt`,
`lastVerifiedAt`, `freshness`. Импорт или обновление не запускаются. Для больших
карт рейтинг также ограничен SQL-бюджетом 5 секунд: агент может передать
`collectionId`, чтобы сузить область. Проверки нового вида: рейтинг, typed/null,
изоляция, полная пагинация корней, бюджет ответа, HTTP и реальный stdio MCP;
`tests/test_data_key_controller.mjs` проверяет изоляцию и запоздалые ответы.
