# Установка Code Atlas из исходников

[Русский](install.ru.md) · [English](install.en.md) · [Обзор](../README.md) · [Установка агентом](../INSTALL_AGENT.md#русский)

Эта инструкция устанавливает локальное приложение для браузера. Наличие публичного native-релиза не предполагается. В репозитории есть рецепты сборки, но рецепт не означает проверенный выпуск для каждой платформы.

## 1. Выберите каталог и Python

Используйте каталог, доступный вашей учётной записи на запись. Для виртуального окружения и Atlas права администратора не нужны. Потребуются:

- 64-битный Python **3.12 или 3.13** с `venv` и `pip`. Эти версии использовались в локальных source-проверках; это не гарантия наличия всех закреплённых native-зависимостей для любой ОС/CPU. На Apple Silicon используйте ARM64 Python.
- Git, если будете клонировать/обновлять checkout или выполнять Git-операции. Вместо клонирования можно распаковать ZIP исходников.
- Сеть для первой установки зависимостей либо заранее подготовленный совместимый wheelhouse. Запуск подготовленного окружения не повторяет установку.

Возьмите URL репозитория у издателя. Замените `<repository-url>` ниже: это шаблон, а не адрес. Если checkout уже есть, проверьте его и используйте корень, не клонируя поверх него.

```sh
git clone "<repository-url>" code-atlas
cd code-atlas
```

Node.js нужен для JavaScript-проверок разработки и пересборки wiki, а не для этого запуска в браузере. Дополнительные семантические анализаторы могут иметь собственные требования к Node/.NET/Java/Python.

## 2. Создайте окружение и запустите Atlas

Выполняйте команды из каталога с `requirements.lock` и `atlas/`. Активировать окружение не нужно. Если `.venv` уже существует, сначала проверьте его Python/версию и владельца; осознанно используйте его либо выберите новый каталог установки, не пересоздавая неизвестное окружение.

**macOS / Linux (POSIX shell):**

```sh
python3 --version
python3 -c "import platform,struct; print(platform.machine(), struct.calcsize('P') * 8)"
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip check
.venv/bin/python -m atlas.cli --version
.venv/bin/python -m atlas.cli --open
```

**Windows PowerShell:**

```powershell
python --version
python -c "import platform,struct; print(platform.machine(), struct.calcsize('P') * 8)"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m atlas.cli --version
.\.venv\Scripts\python.exe -m atlas.cli --open
```

Если `python` в Windows выбирает другую версию, явно используйте установленный интерпретатор, например `py -3.13 -m venv .venv`. Дальше используйте созданный `.venv\Scripts\python.exe`.

Оставьте терминал открытым. Если браузер не открылся, перейдите на **http://127.0.0.1:8765**. Проверьте **http://127.0.0.1:8765/api/health**: готовый сервер возвращает `status: "ok"`. Это проверка готовности HTTP, а не успешного анализа проекта. Остановить сервер — `Ctrl+C` в его терминале.

Для повторного запуска нужна только последняя команда. В macOS/Linux `sh start.sh --open` запускает существующую `.venv`, не устанавливая и не обновляя пакеты. В Windows используйте команду Python выше. Не запускайте `setup-offline.sh`, пока не подготовлен его wheelhouse.

Atlas слушает loopback и рассчитан на одного локального пользователя. Не превращайте его в публичный сетевой сервис. Если другой Atlas уже использует этот каталог данных, используйте его либо остановите осознанно; не удаляйте его lock и не завершайте неизвестный процесс. Другой порт сам по себе не создаёт отдельный профиль данных. Для намеренно независимого профиля передайте **оба** параметра: `--port 8877` и `--data-dir` с новым абсолютным каталогом вне исходников/анализируемых репозиториев. Этот же порт используйте в последующих URL настройки MCP.

## 3. Постройте первую карту

1. В Atlas выберите локальный репозиторий по **абсолютному пути**, затем нажмите **«Построить карту»**. Начните с небольшого своего проекта или проекта, который разрешено исследовать. Клонирование удалённого проекта — отдельное сетевое действие.
2. Дождитесь публикации снимка. Фоновые здоровье/поиск могут продолжить работу; их прогресс не означает исчезновение карты кода.
3. Найдите известный метод или файл, откройте его и проверьте исходник и основания вызовов. Ещё одна отправная точка — каталог входов.
4. После изменения исходников нажмите **«Обновить индекс»**. Сохранённые снимки не следуют за изменениями рабочих файлов автоматически.

Карта фиксирует статические основания, а не выполнение. Пропущенные связи, вычисляемые имена топиков/таблиц и динамический dispatch могут остаться неизвестными. [Работа с картой](wiki/Explore-Code.md).

## 4. Подключите локального агента по MCP

Оставьте Atlas запущенным на **том же компьютере**, где работает MCP-клиент. Интеграция запускает **stdio-прокси**: HTTP URL ниже выдают конфигурацию, а не являются HTTP MCP endpoint. Облачный агент не получает доступ к loopback вашего компьютера.

Откройте в Atlas **«Для агентов · Cursor / MCP»** либо прочитайте:

- [Настройка и область доступа](http://127.0.0.1:8765/api/agent-setup)
- [JSON для клиентов с `mcpServers`](http://127.0.0.1:8765/api/agent-setup/config)
- [TOML для Codex](http://127.0.0.1:8765/api/agent-setup/config?format=toml)
- [Машиночитаемый список проектов](http://127.0.0.1:8765/api/projects)

Для работы с репозиторием возьмите его настоящий ID из списка. Добавьте `?projectId=PROJECT_ID` к URL JSON либо `?projectId=PROJECT_ID&format=toml` для TOML. Замените и URL-кодируйте ID; это не путь и не ID снимка. Используйте настройку без scope только при намеренном доступе ко всему хосту.

Ответ содержит настоящий executable Python, `PYTHONPATH`, порт и необязательный scope проекта. **Объедините только запись `code-atlas-agent`**, сохранив другие серверы/настройки. Перед редактированием сохраните копию существующего config; уже имеющуюся запись обновляйте осознанно, не создавая повторные ключи.

- Cursor: объедините JSON с нужным `.cursor/mcp.json` (проектным или клиентским).
- Codex: объедините таблицы TOML с `config.toml` клиента, обычно `~/.codex/config.toml`.
- Другие клиенты: используйте их поддерживаемый формат stdio MCP; путь Cursor к ним автоматически не относится.

Готовые навыки находятся в [каталоге навыков](../skills/README.md) и в `/api/agent-setup/skills`. Пакет `code-atlas` нужен для работы с картами, а `code-atlas-engines` помогает проверять и настраивать движки. Установите полные папки навыков для выбранного клиента и отдельно подключите MCP по шагам выше.

Из корня Atlas выполните `python3 scripts/install_agent_skills.py --client codex --project-root "/path/to/target-project"`, подставив путь к анализируемому проекту. В Windows используйте `python` и путь Windows. Для Cursor укажите `--client cursor`. Сначала проверьте показанные пути, затем повторите команду с `--apply`. Установщик сохраняет локальные правки в существующих папках навыков.

Переподключите/включите сервер в клиенте, затем **начните новый чат** для обновления списка инструментов. Попросите вызвать `list_projects`; для разрешённой карты — `search_nodes` и `describe_node` с полученными scope проекта/снимка. Сохранение config не доказывает подключение клиента. Разделяйте настройку и реально выполненные вызовы. Если executable переместился или порт изменился, получите config заново и переподключитесь.

## 5. Дополнительные возможности

Публичный пакет включает веб-интерфейс для карт исходников и данных. Захват открытой страницы требует отдельно поставляемого браузерного расширения и SDK AG Privacy. Без них Atlas отклоняет захват. [Браузерные карты](browser-sessions.md)

В закреплённое source-окружение входят Graphify и базовые парсеры. Дополнительные языковые семантические движки уточняют отдельные факты; доступность зависит от совместимых локальных runtime и включённых модов/настроек. В **«Моды»** проверьте доступность движка, запустите проверку совместимости для выбранной карты и различайте **найден / совместим / реально применён**. Установка приложения не доказывает обогащение снимка движком. [Моды](mods-and-graphify.md).

Семантическому поиску нужна отдельно подготовленная локальная embedding-модель; поиск по именам и карта работают без неё. Не скачивайте embedding-модель или LLM как обязательный этап установки. [Семантический поиск](semantic-search.md).

Отдельное desktop-окно необязательно. В том же окружении установите `packaging/requirements-desktop.txt`, затем выполните `python -m atlas.cli --desktop` его executable. macOS использует WKWebView, Windows требует WebView2 Runtime, Linux — QtWebEngine, системные GUI-библиотеки и графическую сессию. Если GUI-стек недоступен, используйте браузер. [Требования desktop/сборки](../packaging/README.md).

Для офлайн-подготовки на машине с **той же ОС, архитектурой CPU и ABI Python** POSIX-скрипты `sh prepare-offline.sh` и `sh setup-offline.sh` готовят/используют `wheelhouse/`. Это не Windows-установщики. На любой платформе совместимый подготовленный wheelhouse можно установить Python вашего окружения командой `-m pip install --no-index --find-links wheelhouse -r requirements.lock`. Недостающие wheels нужно подготовить заранее, а не незаметно скачивать при офлайн-запуске.

## 6. Данные и обновления

Каталоги данных пользователя по умолчанию:

| ОС | Каталог данных |
| --- | --- |
| macOS | `~/Library/Application Support/Code Atlas` |
| Windows | `%LOCALAPPDATA%\Code Atlas` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/code-atlas` |

Locator существующей desktop-установки может выбрать другой каталог. `--data-dir` имеет приоритет; `ATLAS_DATA_DIR` также позволяет задать путь. Фактический каталог выводится в терминале при старте. Храните его вне приложения/исходников/анализируемых каталогов. Управляемые клоны и копии лежат рядом как `<data-dir>-repositories` и `<data-dir>-backups`. Не коммитьте эти каталоги и MCP-config с локальными путями.

Для обновления source-checkout:

1. Остановите Atlas и отключите его MCP-процессы до изменения окружения. Сохраните свои правки исходников и запишите каталог данных. Не используйте `git reset --hard` или `git clean`, чтобы подогнать checkout под обновление.
2. Получите выбранную издателем ревизию в чистом checkout. При использовании Git сначала проверьте `git status`; fast-forward выполняйте только осознанно, когда он уместен.
3. Повторите `-m pip install -r requirements.lock` и `-m pip check` Python вашего окружения, затем запустите с тем же каталогом данных. После изменения правил анализа обновите карту.
4. Если пути/порт изменились, обновите config MCP; переподключитесь и начните новый чат.

Данные находятся отдельно от checkout. Для явной резервной копии при остановленном Atlas выполните `-m atlas.cli --backup-data` Python вашего окружения (добавьте тот же `--data-dir`, если он задан); команда выведет путь архива. Не удаляйте данные или marker схемы ради обхода несовместимости. Используйте совместимую версию либо отдельно согласованный перенос. Обновление native-пакета — другой сценарий: [packaging/UPDATING.md](../packaging/UPDATING.md).

## Диагностика и границы проверки

| Симптом | Что проверить |
| --- | --- |
| Нет `venv`/`pip` | Проверьте выбранный Python. В Linux попросите владельца машины подготовить пакет venv дистрибутива; не используйте `sudo pip`. |
| Не устанавливается закреплённая зависимость | Прочитайте первую ошибку зависимости/платформы; проверьте 64-битную версию Python и CPU. Не снимайте pins ради сокрытия ошибки. Несовместимому wheel/build сочетанию нужно проверенное окружение. |
| Порт занят или удерживается server lock | Найдите/используйте свой существующий Atlas либо выберите независимый профиль данных и порт. Не завершайте чужой сервис и не удаляйте live lock. |
| Браузер не открылся | Откройте напечатанный loopback URL и `/api/health`; проверьте реальную ошибку в терминале. |
| В MCP нет инструментов | Проверьте выданный путь executable, порт и готовность Atlas; переподключитесь и откройте новый чат. Один config-файл не проверяет подключение. |
| Дополнительный движок отсутствует/ошибся | Проверьте настройки мода и реальный статус совместимости/применения. Готовность базовой карты не доказывает семантическое покрытие. |

Команды соответствуют source-интерфейсам репозитория. Есть локальные macOS source/native-проверки; **полная свежая установка из исходников для всех Windows/Linux/CPU-сочетаний здесь не заявляется**. [Граница проверки native-целей](../packaging/BUILD-TARGETS.md). При проверке установки фиксируйте настоящие ОС/CPU/Python, проверку зависимостей, готовность HTTP, результат первой карты и вызов MCP-инструмента.
