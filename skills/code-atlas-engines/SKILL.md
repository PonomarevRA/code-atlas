Применяй при вопросах о Jedi, TypeScript, Roslyn и других семантических движках Atlas, отсутствии разрешённых вызовов или подготовке среды анализа. Обычное чтение карты выполняй имеющимися инструментами Atlas.

## Обнаружение и предложение

Проверь доступные инструменты текущего клиента и адрес работающего локального Atlas. Если MCP отсутствует, прочитай его `/agent-setup.md` и `/api/agent-setup/skills`. Предложи установить полные папки `code-atlas` и `code-atlas-engines`, если они нужны задаче и ещё не доступны. При уже выданном разрешении на установку выполни её. Сохрани существующие серверы и локальные правки навыков. Для клиента без каталога skills можно загрузить этот Markdown и references как инструкции задачи.

## Проверка репозитория

1. Выбери точный checkout и актуальный снимок. Используй инструменты временной checkout-карты, когда они доступны. Для проверки настроек текущий контракт принимает зарегистрированный projectId. Если у временной карты нет собственного semantic API, явно укажи этот пробел и сопоставь регистрацию с тем же исходным каталогом. При отсутствии такой регистрации предложи её создание для выбранного проекта, учитывая разрешение пользователя.
2. Прочитай `inspect_semantic_engine_settings` или `GET /api/semantic-engines/settings`. Определи фактические языки и нужные профили выбранного проекта. Учитывай основной код, тесты и native-компоненты раздельно.
3. Для нужного профиля вызови `inspect_semantic_engine_settings(modId, projectId)`. Существующий executable подтверждает наличие. `get_semantic_engine_status` показывает доступность и статус выбранной карты.
4. Выбери несколько известных узлов с актуальными source hashes. Запроси их описание и дождись завершения enrichment. Для явной повторной проверки используй документированный POST semantic-enrichment с snapshotId, nodeIds и force. При тайм-ауте сначала прочитай статус, поскольку работа могла продолжиться.
5. Проверь queryCount, rawFacts, projectedFacts, rejectedFacts, confirmedEdges, причины partial и confidence опубликованных фактов. Прочитай результат через get_node/describe_node и сравни с исходными рёбрами. Отмечай уже известный вызов и unknown отдельно от новой подтверждённой связи.

## Настройка по результату

Когда отсутствие движка мешает задаче, предложи конкретное изолированное окружение, изменяемые пути и ожидаемую проверку. Для уже разрешённой настройки действуй в согласованных пределах. Host-global путь одного профиля используется разными картами, поэтому сохраняй остальные поля и сообщай об изменении.

Для команд установки, полей API и ограничений C# прочитай [references/setup.md](references/setup.md). Устанавливай только нужные выбранному проекту пакеты. После настройки повтори фактический запрос на том же узле и зафиксируй результат.

Заверши выводом по репозиториям и движкам. Укажи причины недоступности, новые полезные факты, непроверенные языки и размер выборки. Отсутствие semantic enrichment совместимо с доступной базовой картой Graphify/AST.
